## 四、回答你的问题：额外空间究竟额外在哪里

### 先确定从哪一刻开始分析

假设调用`is_anagram(s, t)`时，两个字符串已经在内存里。它们是算法的输入。你为了完成判断又建立了两个频率字典，这些是算法工作时新用的存储。

可以用“别人把两箱货送到工作台”来理解：两箱货是输入，你为了清点另拿出的记录本是额外空间。输入已经占地方，但不同清点方法真正新增的东西可能很不一样。

一般讨论时有三个部分：输入空间、辅助空间、输出空间。辅助空间的英文是auxiliary space，就是计算过程另外用的工作空间。算法题里说“空间复杂度”时，经常简写的是额外/辅助空间；也有人统计总空间，所以回答时说明口径。

### 结合你的代码分别数

| 代码或数据 | 这里算什么 | 原因 |
|---|---|---|
| 传进来的`s`、`t` | 输入 | 调用前已有的字符数据 |
| `word_s`、`word_t` | 辅助空间 | 你的算法为了统计另建的字典 |
| `letter_s`、`letter_t` | 少量辅助状态 | 反复使用固定数量的名字，不是每轮永久多存一个变量 |
| 最后返回的`True/False` | 输出 | 只有一个判断结果，大小不随字符串长度增长 |

即使两个字符串有十万个字符，如果只使用小写英文字母，每个字典仍最多26项。字符总量增加不一定让“不同字符种类数”增加，因此不能只看到字典就固定回答O(n)。

当题目允许的字符种类随输入增长时，可写O(k)，k代表本次出现的不同字符数，最多不超过n+m。固定26种字母时写O(26)=O(1)。通常按每个计数和索引占常量空间的机试分析模型讨论，不要求现在分析超大整数位数。

如果统计“总空间”，输入本身还有O(n+m)，所以总量可以写O(n+m+k)。面试表达可以是：“我分析的是额外空间，使用了两个频率字典，O(k)；本题固定26个小写字母，所以是O(1)。”

### 输出列表要不要算

输出可能很大时，明确单列最清楚。例如返回n个元素的新列表，输出本身就是O(n)，即使过程中只额外用了几个计数器，也不能说程序总共只占O(1)。可以说“辅助空间O(1)，输出空间O(n)”。有的题目把结果容器也计入额外空间，应以题目约定为准。

你的`load_job_skills`返回全部岗位列表：这个结果的大小随文件内容增长。磁盘文件本身不是已经放入内存的字符串，读出来并保留的数据要计入内存占用。设文本规模是N字符，结果总体O(N)；逐行处理只是避免再保存一份完整文件字符串，不会让保留的结果消失。

### 先学会这三个判断

- 循环十万次，但只反复更新一个计数器：额外空间通常O(1)。
- 循环十万次，每次往一个列表追加并保留：新列表会增长到O(n)。
- 用参数接住已经存在的列表，没有复制它：不会仅因传参就产生一份新列表。以后学习可变对象时会继续练习这个区别。

不需要背复杂定义。看代码时问：“为了这次计算，我又建立了哪些容器？最多同时留下多少数据？”

## 五、`return`的位置：什么时候已经足以确定答案

专业上这是控制流程（control flow），也就是程序下一步走向哪里。`return`执行后，整个函数调用结束，不只结束当前循环。

两数之和找到符合条件的两个索引，已经完成题目要求，可以立即返回。读取全部岗位时，刚看到两条并不能确定最终列表，后面还有数据要处理。

用一个与作业不同的小例子观察：

```python
def add_positive_numbers(numbers):
    total = 0
    for number in numbers:
        if number > 0:
            total += number
    return total


assert add_positive_numbers([2, -1, 5]) == 7
assert add_positive_numbers([]) == 0
```

如果把`return total`移到循环里面，第一次循环就可能返回，后面的5没有机会被计算。保留在循环后面，空输入也会返回初始值0。

正常走到函数末尾却没有执行任何`return`时，Python默认返回`None`。`None`表示没有提供一个具体结果；`[]`则是一个明确的空列表。调用者可以对`[]`求长度，却不能把`None`当列表用。

## 六、新理论：文件关闭与异常处理分别做什么

异常（exception）是程序运行途中报告的一种错误，例如路径不存在时的`FileNotFoundError`。语法正确不代表运行一定成功。

对普通文件对象使用`with open`时，离开作用范围会执行关闭动作；这个关闭动作本身不意味着错误被解决。好比用完房间后把门锁好，房间里的工作仍可能没有完成。

如果打开文件之前就找不到路径，文件根本没成功打开，自然也没有已打开的文件需要关闭。[Python文件读取说明](https://docs.python.org/3.11/tutorial/inputoutput.html#reading-and-writing-files)

### `try/except`的最小语法

先用已经认识的整数转换看一个不同于作业的例子：

```python
try:
    number = int("abc")
    print("转换完成")
except ValueError:
    print("这段文字不是整数")

print("继续执行后面的代码")
```

`try`缩进内先尝试执行。`int("abc")`无法转换，产生`ValueError`，所以跳过“转换完成”。匹配的`except ValueError`接住这种错误，打印提示；处理结束后才继续执行最后一行。

`except`后面的名字指定处理哪种错误，不需要导入库。处理文件找不到时使用`FileNotFoundError`。未被匹配处理的异常会继续向外传递，若始终无人处理，本次运行会以错误结束。[Python异常处理教程](https://docs.python.org/3.11/tutorial/errors.html#handling-exceptions)

### 三种情况的区别

| 情况 | 结果 |
|---|---|
| 成功打开并读完 | 得到内容，离开`with`关闭文件 |
| 成功打开，但处理内容时出错 | 离开`with`关闭文件，错误继续向外传递 |
| 找不到文件路径 | 打开失败，是否能继续取决于外部有没有处理这种错误 |

主项目今天先验收成功读取路径。你能口述上面三种情况，就完成这部分基础学习；愿意多练15分钟，再做任务4处理缺失文件。

成功读到一个空文件，和根本没有找到文件，是两种不同结果。以后做模型评估时，“没有样本”与“数据读取失败”也不能混成一个成功报告。

## 七、字典顺序与相等：把你的注释校准成正确知识

Python字典会记住新键的插入顺序，但`==`判断的是键值对应关系。

```python
first = {"git": 1, "python": 2}
second = {"python": 2, "git": 1}
assert first == second
```

它们遍历时先看到的键可能不同，拥有的技能及次数却相同，因此比较相等。字母异位词正好需要“次数相同就算相同”，不要求字符的出现顺序相同。[Python字典的顺序与相等规则](https://docs.python.org/3.11/library/stdtypes.html#mapping-types-dict)

注意，比较两个字典不是看一眼变量名就完成，通常需要检查其中的键值。普通字符计数字典的相等比较平均O(k)，k是不同键的数量。两段O(n)的计数加上O(k)比较，仍可以整体写成平均O(n+m)。

### 面向对象支线第一课：类把一份数据和操作放在一起

先不用记一串术语。你以前用函数处理外部传来的列表；现在提出一个新需求：程序中有两张名牌，每张保存自己的文字，还能各自改名。我们想把“这张牌的文字”和“修改这张牌的动作”放在一起。

面向对象编程（object-oriented programming，OOP）是一种组织程序的方式：用对象保存相关状态，并通过方法操作它。人话是：以前主要关注“执行什么步骤”，现在还关注“这些数据属于谁”。它不取代函数，更不会自动让算法变快。

| 术语 | 准确含义 | 在名牌例子里 |
|---|---|---|
| 类（class） | 定义这一类对象的数据组织和行为 | `NameTag`规定名牌可以保存文字、改名 |
| 对象/实例（object/instance） | 按这个类创建出的具体对象；这里两个词指同一件具体事物 | 入口名牌与出口名牌是两个实例 |
| 实例属性（instance attribute） | 通过某个实例访问、保存在该实例上的数据 | 每张牌自己的`text` |
| 方法（method） | 定义在类中的函数；普通实例方法被对象调用时，会收到这个对象 | `rename`修改当前这张牌的文字 |

类不是某一张具体名牌。像菜谱与做出的两份饭，菜谱相同，不代表两份饭是同一份。这个比喻只帮助区分类与实例，不表示Python会自动复制所有共享数据。

#### 1. 先看定义，不是今天计数器作业的答案

```python
class NameTag:
    def __init__(self, text):
        self.text = text

    def rename(self, new_text):
        self.text = new_text
```

逐行理解，不要整段背：

- `class NameTag:`开始定义一个类，名字由我们取；冒号和缩进仍表示“下面的内容属于它”。此处只定义规则，没有创建入口或出口名牌。
- `def`还是定义函数的关键字，只是这次函数放在类里面。
- `__init__`是特殊方法名，前后各两个下划线。通常调用`NameTag(...)`创建实例时，Python会用它设置这个实例的初始状态。准确说它负责初始化，不是负责分配对象的所有工作；今天不用学习更底层的创建机制。
- `self`表示这次正在处理的实例。它是通用命名约定，不是Python关键字；学习与工作中保持这个名称。
- 右边的`text`是本次调用传来的参数；左边的`self.text`是当前对象的属性。`self.text = text`把输入保存到该对象上。方法调用结束后，仍可通过这个对象找到属性。
- `rename`接收新的文字，用赋值替换当前对象的属性。它没有返回具体数据，调用结果就是`None`；修改属性与返回数据是两件事。

你可以把`self.text`读成“这一个对象的文字”。点号用于访问对象的属性或方法，和你已经写过的`skills.append(...)`属于同一种访问写法。

#### 2. 再看两个对象分别怎样变化

```python
entrance = NameTag("入口")
exit_tag = NameTag("出口")
entrance.rename("接待处")
print(entrance.text)
print(exit_tag.text)
```

第一行创建一个实例，把它交给变量`entrance`引用；初始化时`self`指向这个新实例，`text`收到`"入口"`。第二行创建另一个实例，保存`"出口"`。第三行只修改第一个实例，所以最后输出依次是“接待处”“出口”。

为什么调用`entrance.rename("接待处")`只写一个参数，定义却有两个？因为通过对象调用普通实例方法时，Python会自动把该对象交给`self`；你只提供新的文字。就这个例子而言，它相当于`NameTag.rename(entrance, "接待处")`，后者只用于解释机制，不要求你平时这样调用。

这里的实例属性会在对象仍可使用时保留，不是自动保存到了磁盘。关闭程序重新运行，要重新创建对象；持久保存是以后另外的文件功能。

#### 3. 局部变量与实例属性，别从一个极端走向另一个

`new_text`只服务于本次方法调用；`self.text`则描述某一张名牌目前的状态。不要因为学了`self`，就把方法里所有变量都改成实例属性。

例如LeetCode的`Solution`是平台规定的类名，`Solution()`创建对象，再调用它的解题方法。你的一次字符计数通常仍应放在方法内部的局部字典里，每次调用重新建立。否则上次解题的数据可能残留，影响下一次输入。`Solution`没有需要额外设置的初始状态时，不必为了形式补写`__init__`。

判断标准是：“这是这个对象需要记住的状态，还是这一次计算临时用的东西？”之后的可变容器与类属性课会专门练共享数据问题，今天不提前塞进来。

#### 4. 封装不是把变量藏起来就算完成

封装（encapsulation）在这里指把相关数据和操作组织到一个对象中，并提供清楚的使用方式。人话是：使用名牌的人知道怎么读文字、怎么改名，不需要每次重新拼一套数据和函数。

Python中的普通属性通常可以从外部读取或修改；`entrance.text`就是正常访问。以后看到`_text`，开头一个下划线主要表示“这是内部细节，请优先使用公开方法”的约定，不是一道强制上锁的门。今天的计数器可以使用公开属性，不要求写一堆取值、设值函数，也不引入装饰器或双下划线技巧。[Python官方类教程](https://docs.python.org/3.11/tutorial/classes.html)、[初始化方法说明](https://docs.python.org/3.11/reference/datamodel.html#object.__init__)

#### 5. 这和之后手写Transformer有什么关系

模型也有需要保留的状态，例如训练得到的参数；每次输入、计算出的中间结果则属于某一次计算。之后会学用`nn.Module`组织模型，在`__init__`中定义子层，在`forward`中描述输入怎样经过各层，通常通过`model(x)`运行模型。今天只知道这些代码需要类与对象基础，不用导入PyTorch，也不用背模型外壳。[PyTorch构建网络教程](https://docs.pytorch.org/tutorials/beginner/basics/buildmodel_tutorial.html)

今天支线的验收非常具体：你能独立创建两个学习计数器，操作其中一个而不改变另一个，并解释数据属于谁。写出类只是起点；后续仍要分别学会数学运算、注意力与完整训练流程。
