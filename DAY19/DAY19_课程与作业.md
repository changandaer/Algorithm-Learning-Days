### 01：Python两数之和

~~~python
class Solution:
    def twoSum(self, nums, target):
        seen = {}
        for index in range(len(nums)):
            needed = target - nums[index]
            if needed in seen:
                return [seen[needed], index]
            seen[nums[index]] = index
        return []


solution = Solution()
~~~

### 04：神经元候选参数学习

保持你“逐个候选、收集整组预测、比较整组标签”的思路。下面用临时神经元试算候选，复用已有forward，让两处计算一致，不重新写另一套神经元公式。

~~~python
class SingleNeuron:
    def __init__(self, weight, bias):
        self.weight = weight
        self.bias = bias

    def forward(self, x):
        z = self.weight * x + self.bias
        if z > 0:
            return z
        return 0

    def fit(self, xs, ys, candidate_weights):
        for candidate_weight in candidate_weights:
            trial_model = SingleNeuron(candidate_weight, self.bias)
            predictions = []
            for x in xs:
                predictions.append(trial_model.forward(x))
            if predictions == ys:
                self.weight = candidate_weight
                return candidate_weight


neuron_a = SingleNeuron(0, 1)
neuron_b = SingleNeuron(0, 0)
xs = [0, 1, 2]
ys = [1, 3, 5]
candidates = [1, 2, 3]

assert neuron_a.fit(xs, ys, candidates) == 2
assert neuron_a.weight == 2
assert neuron_a.bias == 1
assert neuron_a.forward(3) == 7

assert neuron_b.fit([1, 2], [3, 6], candidates) == 3
assert neuron_b.forward(3) == 9
assert neuron_a.weight == 2

assert neuron_a.fit(xs, [1, 2, 3], candidates) == 1
assert neuron_a.forward(3) == 4
assert neuron_b.weight == 3
assert neuron_b.bias == 0

assert neuron_a.fit([-1, 0, 1], [0, 1, 3], candidates) == 2
assert neuron_a.forward(-1) == 0
assert neuron_a.forward(3) == 7
assert neuron_a.weight == 2
assert neuron_a.bias == 1
assert xs == [0, 1, 2]
assert ys == [1, 3, 5]
assert candidates == [1, 2, 3]
~~~

新增部分拆开理解：

- trial_model用当前候选权重和固定偏置建立一个试算对象；每个候选只建一次。
- trial_model.forward(x)使用完整的ReLU神经元计算，不只比较中间量z。
- predictions只是本轮临时预测列表，用完即可丢弃。
- 与全部标签一致后，self.weight保存选中的权重；self仍是调用fit的正式模型。
- 后面的return把整数交回调用者；“返回一个数”和“在模型里保存参数”是两件事，这里都完成了。

这不是唯一正确写法。你也可以在原先fit计算中明确补上同样的ReLU，或者先让当前模型试用候选再调用自身forward；只要两处计算一致、最终参数正确即可。示范选择临时对象是为了不重复维护两套预测公式，不要求背这一种组织方式。

| 项目 | 你的代码 | 示范与评价 |
|---|---|---|
| 检查全部样本 | ys_hat与ys整表比较 | 正确保留，不必改成老师偏好的计数或标志 |
| 预测公式 | fit中只有线性计算，forward有ReLU | 必须修正，涉及学的是哪一个模型 |
| 保存权重 | self.weight = candidate_weight | 代码正确；不是存入ys_hat |
| A再次学习 | 先重新创建neuron_A再fit | 没验证同一对象更新；老师补测证明你的代码支持，无需重写类 |
| 测试方式 | 打印了预期的六个数 | 示例包含断言和负中间值，以便错误直接被发现 |

## 四、Python新课：已知总和，怎样知道一边的和

### 1. 中心下标不是数组正中间的位置

中心下标（pivot index）是一个位置：严格位于它左侧的数之和，与严格位于它右侧的数之和相等。人话：像找一个分隔点，左右两堆数字的总量一样；分隔点自己不放进任何一堆。

例如[2, 4, 1, 6]：

| 检查的下标 | 当前数字 | 左边有哪些数 | 左和 | 右边有哪些数 | 右和 |
|---:|---:|---|---:|---|---:|
| 0 | 2 | 没有 | 0 | 4、1、6 | 11 |
| 1 | 4 | 2 | 2 | 1、6 | 7 |
| 2 | 1 | 2、4 | 6 | 6 | 6 |
| 3 | 6 | 2、4、1 | 7 | 没有 | 0 |

答案是下标2，不是当前数字1，也不是左右共同的和6。位置两侧的元素数量可以不同，“中心”说的是和相等，不是左右各有几个数。

一侧没有元素时，和按0处理。所以首尾都有可能是答案；只有一个元素时，两侧都是空，中心下标为0。负数也参加正常加法，不能根据数大数小随意跳过位置。

### 2. 总和、左和、当前值、右和的关系

这是今天真正要掌握的关系，不是新语法：

**总和＝左边的和＋当前数字＋右边的和。**

因此：

**右边的和＝总和−左边的和−当前数字。**

用上面下标2验算：总和13、左和6、当前数字1，右和就是13−6−1＝6。不需要为了知道右边的和，再把右边每个数扫一遍。

把它想成账本：已知总金额，扣掉左边这堆和当前这一项，剩下的就是右边。注意扣掉的是当前位置的数字，不是下标2这个编号。

数学关系解释了“能复用哪些信息”；完整循环、判断顺序与三步分析仍由你写。你需要自己想清：一个变量叫“左边的和”时，在检查当前位置的那一刻，它是否已经包含当前数？先用上面某一行核对含义，再写代码。

### 3. sum是什么，什么时候可以用

内置函数（built-in function）是Python直接提供、不需import的函数。sum接收一组可相加的数，默认从0开始累加，返回一个总数：

~~~python
values = [5, -2, 4]
total = sum(values)
assert total == 7
assert values == [5, -2, 4]
assert sum([]) == 0
~~~

它不会返回每个阶段的结果，也不会修改这个列表。对于本课的整数列表，求总和仍需访问各元素，不是“用一个函数名就没有计算成本”。[Python官方sum说明](https://docs.python.org/3.11/library/functions.html#sum)

今天允许用一次sum得到整表总和，也允许自己写一次求和循环。不要在当前方法里写sum = 0后又调用sum(nums)，因为此时这个名字指向整数，不再是你想调用的函数；可以改用total或left_sum等自己能解释的名字。

题目返回值的形状不决定效率。若每个位置都重新统计左右两边，整体可能O(n²)；如果复用总和与累计信息，就有机会用O(n)时间完成。先确保结果符合题意，再检查重复计算，不要求死背某段模板。

### 1. cin：不用每换一个数都改源码

标准输入（standard input）是程序接收输入的通道；你在终端直接运行时，通常来自键盘。std::cin是用于读取它的标准库对象。人话：程序等你输入，再把读到的数字放进变量。

~~~cpp
#include <iostream>

    std::cin >> count;

}
~~~

运行后输入5并按回车，程序输出7。没有输出、光标停着时，可能只是正在等输入，不一定卡死。

逐句对应：

- int count = 0先建立整数变量；读取成功后，输入值会替换0。
- std::cin >> count用提取运算符（extraction operator）>>读取一个整数并放入count；不是Python的input()返回字符串再自己转int。
- cout使用<<输出，cin使用>>输入；它们不是可以随意对调的箭头。
- 本课保证输入是合法整数。输入字母、缺失输入、输入失败恢复以后再教，不加入今天验收。

可以连续读取两个数：

~~~cpp
#include <iostream>

int main() {
    int first = 0;
    int second = 0;
    std::cin >> first >> second;
    std::cout << first + second << "\n";
    return 0;
}
~~~

输入2 5或分两行输入2和5，都会得到7。整数读取会用空格、换行等空白分隔，不要求固定同一行。[C++标准输入的提取操作](https://learn.microsoft.com/en-us/cpp/standard-library/using-extraction-operators?view=msvc-170)

今天一个程序只处理一组输入。跑完后要检查下一组，就重新运行程序，不提前写while循环。

### 2. 比较表达式与bool

比较表达式的结果是布尔值（boolean）：true表示成立，false表示不成立。人话：不是再算一个数量，而是回答“这件事是不是这样”。

| 写法 | 含义 | 小例子 |
|---|---|---|
| a > b | 严格大于 | 5 > 5为false |
| a >= b | 大于或等于 | 5 >= 5为true |
| a < b | 严格小于 | 4 < 5为true |
| a <= b | 小于或等于 | 5 <= 5为true |
| a == b | 相等 | 5 == 5为true |
| a != b | 不相等 | 4 != 5为true |

布尔变量的类型是bool，值写小写true、false；不是Python的True、False。可以保存比较结果，但直接在if里写比较即可，不强制增加一个变量。

=仍然表示赋值，==才比较；不要写成if (score = 60)来问分数是否60。把阈值相等的输入单独测一次，能很快发现该用>还是>=，这属于判断知识本身。

### 3. if/else：只执行条件对应的代码

下面的小例子判断一个数的符号，不是今天作业的阈值答案：

~~~cpp
#include <iostream>

int main() {
    int value = 0;
    std::cin >> value;

    if (value > 0) {
        std::cout << "positive\n";
    } else if (value == 0) {
        std::cout << "zero\n";
    } else {
        std::cout << "negative\n";
    }
    return 0;
}
~~~

分别输入4、0、−2，会分别输出positive、zero、negative。

- 条件写在圆括号里，大括号装这一分支要执行的语句；不同于Python的冒号和缩进语法。
- if先检查第一种情况；成立就执行它，整条链后面的else if与else不再执行。
- else if表示“前面的情况不成立，再检查这一种”；else接住前面都不成立的情况，没有额外条件。
- if条件后不要多写分号。if (条件);会让条件控制一条空语句，后面的代码不再按你的预期受它控制。
- 三个独立if会各自检查，不等于一条if/else if/else链。输出互斥等级时，要想清楚是否只应选择一个分支。[C++条件分支说明](https://learn.microsoft.com/en-us/cpp/cpp/if-else-statement-cpp?view=msvc-170)

例如先检查“小于某个门槛”，没通过这项检查才来到下一个分支，此时你已经知道它不小于前面的门槛。因此可以用有顺序的判断表达连续区间，不需要今天额外学习一套复杂条件写法。

### 2. 本日教材位置与问题

教材：[《神经网络与深度学习（邱锡鹏）》](../../学习资料/AI%20agent/神经网络与深度学习%20(邱锡鹏).pdf)，1.3、1.3.1、1.3.2，书内第7—10页，对应PDF第22—25页，到1.4标题前为止。已核对正文、表1.1和图1.3；下面使用自己的数值例子，不要求照书背诵。

昨天x已经是一个数，神经元能直接乘权重。如果输入是“猫”“狗”“车”，把字当字符串直接乘一个浮点权重，并不是模型需要的数值计算。必须先设计一种输入表示。

表示（representation）是交给模型的一种描述方式。人话：把原始信息换成模型能处理、又尽量保留有用信息的一串数。

表示学习（representation learning）则是让表示本身从数据中学出来。手工写出一张字典只是给了表示，不会因为写进类就自动变成“学到了表示”。

### 3. 语义鸿沟：看起来不同，意义可能相同

语义（semantics）就是信息表达的意义；语义鸿沟（semantic gap）指底层数据和我们理解的意义之间的差距。

例如两张猫的照片，一张亮、一张暗，像素数字可能差很多，但人仍把它们看成同类；“小猫”和“猫咪”字符编码不同，却可能表达相近意思。模型若只拿到原始编码，还需要理解哪些差异重要、哪些只是外观或写法。

好的表示应保留对任务有用的区别，让后面的预测更容易。不是所有任务都需要同一种表示：判断颜色时，颜色信息很重要；判断物种时，光照变化未必应改变类别。

教材1.3.2继续说明：表示可以通过多步变换学习，并与后面的预测任务联系起来。今天先看输入怎样组织，DAY20再接多层变换与网络组合；不提前讲矩阵反向传播。

### 4. one-hot：每个类别一个专属位置

向量（vector）在今天先理解为有顺序的一组数字；维度（dimension）就是里面有几个数。我们用Python列表表示向量，暂不需要NumPy。

独热编码（one-hot encoding）让一个类别占一个位置：它的位置是1，其余是0。例如类别顺序固定为红、浅红、蓝、绿：

| 类别 | 四维one-hot |
|---|---|
| 红 | [1, 0, 0, 0] |
| 浅红 | [0, 1, 0, 0] |
| 蓝 | [0, 0, 1, 0] |
| 绿 | [0, 0, 0, 1] |

“热”只是把某个位置点亮的比喻，不涉及温度。类别顺序要固定，否则同一个向量会被解释成不同类别。

优点是身份清楚，没有强行规定“蓝比红大”。如果简单把类别标成1、2、3后直接当连续数值喂给线性模型，就会额外引入数值大小和间隔关系；类别ID可以用于查表，但不等于它本身就是合适的数值特征。

局限是类别很多时，向量很长，大多数位置为0，这叫稀疏（sparse）。而不同one-hot在对应位置没有共同的1，不能单靠这份编码反映“红与浅红比红与蓝更相近”。它能区分身份，不自动表达语义关系。

### 5. 分布式表示：用多个位置共同描述一个类别

分布式表示（distributed representation）把一个对象的信息分散在多个数值位置上共同表达。这里不是多台服务器分布式训练；“分布”说的是信息的表示方式。

教材用颜色帮助理解。沿用我们自己的例子，用0到1的RGB表示红、绿、蓝三种颜色成分：

| 类别 | 三维RGB示意 |
|---|---|
| 红 | [1, 0, 0] |
| 浅红 | [1, 0.5, 0.5] |
| 蓝 | [0, 0, 1] |
| 绿 | [0, 1, 0] |

三项不再各自代表一个类别，而是共同描述颜色。浅红不必专占一个新维度，它可以由已有三个成分组合出来。RGB是这里帮助理解“共同表达”的人造表示，不是从本次训练学出的参数。

神经网络中的词向量也可以用多个坐标共同表达一个词。维度常常远少于词表大小，数值可以为正、负、零；通常称稠密（dense）表示，但这不要求每一项都非零。

别把学到的某个维度武断命名成“可爱程度”或“车辆程度”。除非有专门设计和证据，单个坐标未必能用一个人类概念清楚解释。今天也不因为两个手填向量看起来接近，就声称证明了语义相似。

### 6. Embedding：查表动作，与学到表里的数不是一回事

嵌入（embedding）在本课指把一个离散类别映射成固定长度的数值向量。人话：每个类别有一行属于它的数字，输入类别就取出那一行，交给后面的模型。

可以把三个类别的向量排成表：

| 类别 | 第0项 | 第1项 |
|---|---:|---:|
| 猫 | 1.0 | 0.5 |
| 狗 | 0.75 | 0.5 |
| 车 | 0.0 | 1.0 |

词表（vocabulary）是允许出现的类别集合，这里大小为3；每个向量长度为2。表是3行2列，不是“3个词所以每个向量也必须长3”。

按词表顺序，狗的one-hot是[0, 1, 0]。如果用它选上表的行，第0个输出分量是0×1.0＋1×0.75＋0×0.0＝0.75；第1个分量是0×0.5＋1×0.5＋0×1.0＝0.5。所以取出的向量是[0.75, 0.5]。

这是一行“选中”的数值意义，今天只需手算，不要求实现矩阵乘法，也不必真的生成完整one-hot再查表。后面用整数ID直接定位表的一行，可以避免建立很长的one-hot。

真实神经网络的Embedding层也包含查表动作；训练时表内数值可以随训练目标更新。我们今天只实现已给定表的前向，不训练这张表，不安装PyTorch。可在自己完成后对照[PyTorch官方词嵌入教程](https://docs.pytorch.org/tutorials/beginner/nlp/word_embeddings_tutorial.html)和[Embedding源码所在模块](https://github.com/pytorch/pytorch/blob/main/torch/nn/modules/sparse.py)的接口概念，不读完整仓库、不照抄源码。

人工给定、随机初始化、训练得到，是三种不同来源。今天的数据属于第一种。只有把表接进训练流程、根据目标调整数值并验证效果，才谈得上学到了有用表示；查表次数多不会自动让表示变好。

### 7. 围绕实际部件学习类、属性与方法

今天的类叫EmbeddingTable，它是神经网络输入表示部件的最小实现，不是无关的计数器，也不是完整Transformer。

| 名字 | 今天的职责 | 是否长期保存 |
|---|---|---|
| self.vectors | 当前实例使用的类别→向量表 | 是 |
| token | 本次要查询的类别字符串 | 否 |
| tokens | 本次要转换的类别列表 | 否 |
| encode里的结果列表 | 本次输出的向量序列 | 否 |

构造方法__init__负责接收表并保存在当前实例；forward处理一个类别；encode处理一串类别。方法需要使用当前对象的表，不能写死一个外部全局table_a，否则第二个实例会读错表。这和昨天“临时预测列表”与“保存参数的属性”不是一回事。

封装（encapsulation）在这里是把数据和围绕它的操作组织在一起。不是给属性加下划线就算掌握封装；真正的效果是使用者传入类别，就能通过模型的方法取得正确表示。

只复习一个已会的局部操作，不给完整类：

~~~python
rows = {"甲": [0.5, -1.0], "乙": [1.0, 0.25]}
vector = rows["乙"]
assert vector == [1.0, 0.25]
assert vector[0] == 1.0
assert vector[1] == 0.25
~~~

字典按键取出的是一个列表，列表再按下标取单个数。类里保存了字典之后仍使用同样的操作，不会因为加了self就变成另一种查找算法。

神经元forward返回一个数，EmbeddingTable.forward返回一个向量，它们都叫前向，但计算职责不同。昨天ReLU必须补，是因为fit需要使用那个神经元的完整计算；今天的查表不能擅自对向量做ReLU，负数应原样保留。

### 8. 作业04：实现EmbeddingTable
