## 四、DAY06 全部代码示范答案与评语

### 示范 1：列表标准化去重

```python
raw_text = input("请输入技能，用空格分隔：")
raw_skills = raw_text.lower().split()
unique_skills = []

for skill in raw_skills:
    if skill not in unique_skills:
        unique_skills.append(skill)

print(f"去重后的技能：{unique_skills}")
print(f"技能数量：{len(unique_skills)}")
```

对比你的代码：

- 普通输入去重正确。
- 题目规定空行应输出空列表和数量 0，你的程序却要求继续输入；自动测试只输入一个空行时会遇到 `EOFError`。
- `split()` 本身会忽略首尾和连续空白，这里不写 `strip()` 也可以。
- `is_None` 命名不准确：它保存的是布尔状态，不是 Python 的 `None`；而且本题无需反复输入。
- 你问“为什么要转成列表”：因为我们需要逐项遍历、判断重复并建立新清单；字符串虽然也能遍历，但会逐个处理字符，而不是逐项处理技能。

### 示范 2：技能清单大小写修复

```python
skills = ["python", "linux"]
new_skill = input("请输入一项技能：").strip().lower()

if new_skill == "":
    print("输入技能为空")
elif new_skill in skills:

print(skills)
```

对比你的代码：

- “同一标准化规则”就是：参与比较的旧数据和新数据都统一小写，而不是只处理用户新输入。
- 你保存了修改前后的终端结果，这是很好的回归测试证据。

### 示范 3：第一次损失反弹

```python
losses = [1.0, 0.8, 0.6, 0.7, 0.5]
found_rebound = False

for current_index in range(1, len(losses)):
    previous_index = current_index - 1

    if losses[current_index] > losses[previous_index]:
        print(
            f"第 {previous_index + 1} 轮到第 {current_index + 1} 轮发生反弹："
            f"{losses[previous_index]} -> {losses[current_index]}"
        )
        found_rebound = True
        break

if not found_rebound:
    print("损失没有反弹")
```

对比你的代码：

- 规定列表、无反弹和立即反弹均能正确判断。
- 你用 `index` 和 `index + 1` 比较，与模板从 1 开始并和前一项比较，本质相同。
- `is_bound` 应改成 `found_rebound`。`bound` 通常表示边界，不是反弹。
- 题目还要求输出前一轮、本轮和两个损失值，你只输出了发生反弹的轮次。
- `else: pass` 没有作用，可以删除。

### 示范 4：两数之和使用不同索引

numbers = [2, 7, 11, 15]

对比你的代码：

### 示范 6：岗位共同技能统计器 V1

```python
job_skill_lists = [
    ["Python", "Linux", "Git", "PyTorch"],
    ["python", "C++", "linux", "git"],
    ["PYTHON", "PyTorch", "Linux", "Docker"],
]

all_skills = []

for job_skills in job_skill_lists:
    for raw_skill in job_skills:
        all_skills.append(raw_skill.lower())

unique_skills = []

for skill in all_skills:
    if skill not in unique_skills:
        unique_skills.append(skill)

skill_counts = []

for target_skill in unique_skills:
    current_count = 0

    for skill in all_skills:
        if skill == target_skill:
            current_count += 1

    skill_counts.append(current_count)

common_skills = []

for index in range(len(unique_skills)):
    print(f"{unique_skills[index]}：{skill_counts[index]} 次")

    if skill_counts[index] == len(job_skill_lists):
        common_skills.append(unique_skills[index])

print(f"所有岗位共同技能：{common_skills}")
```

对比你的代码：

- 你已经完成了第一阶段“摊平并小写化”和第二阶段“建立不重复清单”，方向正确。
- 文件最后的 `if` 没有缩进代码块，因此产生 `IndentationError`，程序无法启动。
- 你卡在计数阶段。人话解法是：拿起一种技能，例如 `python`，重新走一遍全部技能，每看到一次就数 1；然后换下一种技能重复。
- 你的 `cols = len(job_skill_lists[0])` 假设每个岗位技能数量完全一样。更安全的写法是直接遍历每个内层列表，因为真实岗位要求长度不同。
- 这道题不是一道标准 Hot 100 题。它把“二维列表、摊平、去重、嵌套计数、平行列表”叠在一起，对第 6 天初学者属于偏难，接近多个 LeetCode Easy 子问题组合后的中等认知难度。并且在真实 Python 中更适合使用尚未学习的字典。我把它安排得过早，这是教学难度设计问题。

## 五、DAY06 理论题示范答案（人话版）

### 1. 变量从哪里来？

变量来自程序运行时“必须记住的事实”。例如查找时必须记住“找到了没有”和“在哪里找到”，所以产生 `found` 和 `found_index`。不是先决定要三个变量，再强行往里面装东西。

### 2. 六格拆题法是什么？

看清输入、看清输出；拿一个很小的例子手算；找出手算时必须记住的状态；找出重复动作；写成人话步骤；最后准备普通、边界和故意拆穿错误的测试。

不需要每天写长文。DAY07 开始压缩成“小样例—分阶段—记状态”。

### 3. 什么是反例？

反例是专门用来推翻错误想法的数据。目标 4 会检查两数之和是否把同一个索引 0 的数字 2 使用两次，因此比普通目标 9 更容易揭露漏洞。

### 4. 两层循环中的 `break`

一个 `break` 只退出离它最近的那层循环。先在内层找到后设置 `found = True` 并 `break`；回到外层后检查 `found`，再执行一次 `break`。

### 5. `found_index = -1` 是什么？

这里的 -1 是**哨兵值（sentinel value）**。专业词听起来复杂，人话就是在门口挂一块“还没找到”的牌子。

`found_index = -1` 只是把数字 -1 放进变量，没有访问列表。只有写成 `skills[-1]` 时，-1 才作为负索引表示最后一个元素。

### 6. 为什么比较两边都要标准化？

如果新输入变成 `"linux"`，旧列表仍是 `"Linux"`，计算机就认为它们不同。像核对身份证一样，比较双方必须采用相同格式，不能只整理其中一边。

### 7. 怎样逐条验收需求？

把题目每个“要求”改写成一行检查表：是否输出索引、是否输出数值、是否阻止同一位置、是否找不到时有提示。每一行都准备至少一个输入和预期输出。程序运行不报错，只说明语法能执行，不代表需求已经完成。

## 六、DAY07 核心方法：三步拆题卡

### 第一步：用最小数据手算

两数之和不要一开始看十个数。先用：

```text
数字：[2, 7]
目标：9
```

人类解法只有一句：选位置 0 和 1，相加得到 9。

### 第二步：把工作切成流水线

岗位技能统计不要一口气写完。切成：

```text
各岗位清单
    ↓ 全部小写并摊平
一个大列表
    ↓ 去重
不重复技能列表
    ↓ 每种技能重新数一遍
次数列表
    ↓ 挑出次数等于岗位数的技能
共同技能
```

每一阶段都能单独 `print()` 检查。前一阶段正确后再写下一阶段。

### 第三步：只记录必要状态

统计一个目标技能，只需要：

- `target_skill`：现在数谁。
- `current_count`：目前看到了几次。

统计多个目标时，每换一个目标，`current_count` 必须重新变回 0。

这就是变量的来源：人手数数时需要一个目标和一个计数器，程序也一样。
