# C++ 核心概念与常见报错整理

## 1. 函数调用语法与函数重载/定义规范

### 问
在 `main` 主函数中调用其他函数时，禁止写声明或者定义函数时候的函数返回值类型吗？例如：
```cpp
#include<iostream>
void add_to(int* target,int delta);

int main(){
    int origin = 10;
    int add = 20;
    int* origin_location = &origin;
    int* copy_location = origin_location;
    
    // 如果写 void add_to(origin_location,add); 报错：不允许使用不完整的类型
    add_to(origin_location,add);
    
    std::cout << *origin_location << ' ' << copy_location << '\n';
    return 0;
}

void add_to(int target,int delta){ // 这里的参数声明与前面不一致
    if(target!=nullptr){
        *target += delta;
    }
}
```

### 答
**是的，调用函数时绝对不能加上函数的返回值类型（如 `void`、`int` 等）。**

如果你在 `main` 函数里写成 `void add_to(origin_location, add);`，编译器会认为你试图在 `main` 内部**重新声明**一个函数，而不是在“调用”它，从而报出语法错误。

**正确的函数调用格式只需要“函数名”和“传入的参数”：**
```cpp
add_to(origin_location, add); // 正确的调用方式
```

> **注意：** 在上述代码底部，定义函数时第一个参数漏掉了 `*` 号（写成了 `int target`），而函数体内部使用了指针操作（`target != nullptr` 与 `*target += delta`），需要修正为 `void add_to(int* target, int delta)` 才能通过编译。

## 2. 指针与数组下标运算符 `[]` 的优先级

### 问
写求和函数时：
```cpp
int sum_values(int* values, int length){
    int total = 0;
    for(int i = 0; i < length; i++){
        total += *values[i];
    }
    return total;
}
```
报错 `"*" 的操作数必须是指针，但它具有类型 "int"`。`values` 不是指针变量吗？

### 答
`values` 确实是 `int*` 指针，但报错原因是**运算符优先级**问题。

在 C/C++ 中，数组下标运算符 `[]` 的优先级高于解引用运算符 `*`。因此 `*values[i]` 的实际执行顺序是 `*(values[i])`：
1. **`values[i]`**：已经取出了对应位置的整数值（类型为 `int`）。
2. **`*`**：试图对这个普通的 `int` 值解引用，因而报错。

### 解决方案
`values[i]` 在底层已经等价于 `*(values + i)`，因此直接去掉 `*` 即可：
```cpp
int sum_values(int* values, int length){
    int total = 0;
    for(int i = 0; i < length; i++){
        total += values[i]; // 直接读取元素
    }
    return total;
}
```

## 3. 指针算术（Pointer Arithmetic）

### 问
`values[i]` 每次 `i` 增加 1，在内存中真实移动时，`values` 会自动增加一个 `int` 大小的内存吗？是因为 `values` 中保存的是 `int` 型数据吗？

### 答
**是的，完全正确！** 这在 C/C++ 中被称为**指针算术（Pointer Arithmetic）**。

当对指针进行偏移或使用 `[i]` 时，编译器不是简单地在内存地址上加 1 个字节，而是**自动跨越所指向数据类型的大小（`sizeof(type)`）**。

* 计算公式：$\text{实际内存地址} = \text{首地址} + ( i \times \text{sizeof(type)} )$
* 若 `sizeof(int) = 4`，`values[1]` 对应的物理偏移为 $+4$ 字节，`values[2]` 为 $+8$ 字节。
* 类型（如 `char*`、`int*`、`double*`）决定了指针每次移动的“步长”。

## 4. 引用（Reference）与拷贝（Copy）的区别

### 问
```cpp
#include<iostream>

int main(){
    int duration = 12;
    int& other_name = duration;
    int copy = duration;

    other_name += 3;
    std::cout << duration << ' ' << other_name << ' ' << copy << '\n';
    std::cout << &duration << ' ' << &other_name << ' ' << &copy << '\n';
    std::cout << (&duration == &other_name) << '\n';
    return 0;
}
```
引用相当于给最初变量重新起了一个名字，所以两者等价；而复制相当于新开辟一块空间并把数据放进去，两者后续没有任何关系，对吗？

### 答
**完全正确。**

1. **引用（`int& other_name = duration;`）**：
   * **本质**：变量的“别名”。
   * **内存表现**：`duration` 与 `other_name` **共享完全相同的内存地址**（`&duration == &other_name` 为 `1`）。
   * **行为**：修改 `other_name` 会同步改变 `duration`。

2. **拷贝/值传递（`int copy = duration;`）**：
   * **本质**：“克隆/复印件”。
   * **内存表现**：`copy` 拥有完全**独立的新内存空间**。
   * **行为**：对 `copy` 的任何修改都不会影响原变量。

## 5. 引用的绑定与指针改指向的对比

### 问
“引用声明时就要绑定对象。绑定后 `other_name = another_value;` 是把值写到原对象，不是让引用改为另一个对象的别名。相比之下，指针 `p` 可以通过 `p = &another;` 改指向。” 这句话怎么理解？

### 答
这句话说明了引用与指针在**不可变更性**上的核心差异：

1. **引用必须在声明时绑定**：不能写未初始化的 `int& ref;`。
2. **引用不能重新绑定**：一旦绑定某变量，它一生都是该变量的别名。执行 `other_name = another_value;` 时，是将 `another_value` 的**数值**写进引用所绑定的原变量，而不是更改绑定的目标。
3. **指针可以随时改指向**：指针变量存的是地址，可以通过赋值语句（如 `p = &another;`）改存另一个变量的地址。

## 6. `const` 关键字与 `const` 引用

### 问
1. `const` 是 `constant` 的缩写吗？
2. 使用了 `const` 之后就不能对 `value` 做任何改动吗？
3. 为什么要用 `const` 引用？

```cpp
void change_const_original(const int& value){
    // value += 5; // 报错：表达式必须是可修改的左值
    std::cout << &value << '\n';
}
```

### 答
1. **缩写**：是的，`const` 是 **constant**（常量、不变的）的缩写。
2. **限制**：使用 `const` 修饰后，**无法通过该名称/通道修改数据**，否则编译器报错。
3. **`const` 引用的优势**：
   * **按值传递（如 `int v` 或 `std::vector v`）**：会发生内存拷贝，大对象开销极大。
   * **普通引用传递（如 `int& v`）**：高效，但无法防止函数内部误改原数据。
   * **`const` 引用传递（如 `const std::vector<int>& v`）**：**兼具高效（零拷贝、不复制容器）与安全（只读，防止误篡改）**。

## 7. `const` 引用的作用域与视角

### 问
如何理解：
1. "const引用不等于原对象从此不能改变：如果原对象本来可修改，外部仍可能通过别的合法名字修改它；这个函数只承诺不通过自己的const引用修改。"
2. "const int* p限制通过*p改整数，但p本身仍可以改指向。"

### 答
这两句话说明 `const` 限制的是**特定的访问视角**，而非改变变量物理上的绝对属性：

1. **`const` 引用是“只读视角”**：
   * 函数接收 `const int&`，意味着函数**承诺不通过这个引用**修改原对象。
   * 但如果原对象在函数外部是普通可变变量，外部代码仍可用其原名修改它。
2. **对照 `const int* p`**：
   * `const` 锁定的是 `*p`（即不能通过 `*p = ...` 修改内容）。
   * 但指针 `p` 本身未被锁定，仍可以通过 `p = &other` 更改指向。

## 8. 容器副本修改与范围 for 循环里的引用

### 问
在 `shifted_copy` 函数中：
```cpp
std::vector<int> shifted_copy(std::vector<int> values, int delta){
    for(int value : values){ // 此处报错/未能修改返回值
        value += delta;
    }
    return values;
}
```
原本期待输出加了 `delta` 后的副本，却依然输出了未修改的数据。为什么？函数形参已经是按值传参的副本，为什么内部 `for` 循环还需要加 `&`？

### 答
### 原因
1. 函数形参 `std::vector<int> values` **按值接收**，确实已经在函数作用域内创建了一个**独立的容器副本**。
2. 但在 `for(int value : values)` 遍历时，`value` 是一个**按值接收的局部变量**，每次循环会将容器内的元素**再次拷贝**给 `value`。修改 `value` 只是修改了这个二次拷贝的临时变量，容器副本本身未变。

### 解决方案
在内部范围 `for` 循环中使用引用 `int&`：
```cpp
std::vector<int> shifted_copy(std::vector<int> values, int delta){
    for(int& value : values){ // 绑定到 values 容器副本内的各元素
        value += delta;
    }
    return values; // 正确返回修改后的容器副本
}
```

### 概念区分
* **形参按值传递（`std::vector<int> values`）**：确保 `main` 函数中的原始容器不被改变。
* **循环中使用引用（`for(int& value : values)`）**：确保能够直接修改**该函数局部容器副本**中的内部元素。

## 9. 普通变量与 `const` 变量传递给 `const` 引用

### 问
当函数参数为 `const std::vector<int>&` 时，把普通的 `values` 和 `const` 限定的 `const_values` 传给它，两者的作用是一样的吗？

```cpp
int total_duration(const std::vector<int>& values);

// main 函数中
std::vector<int> values = {4, 10, 20};
const std::vector<int> const_values = {2, 10, 15};

total_duration(values);       // 允许
total_duration(const_values); // 允许
```

### 答
在**被调函数内部**的表现是一致的，但两者的**权限与安全级别**有本质区别：

1. **兼容性（为什么都能传）**：
   `const std::vector<int>&` 提供了只读访问通道。
   * `const_values` 本身是常量，符合只读限制。
   * `values` 是普通可变变量，传递给 `const` 引用属于**“权限降级使用”**，C++ 允许这种安全的降级行为。

2. **核心区别**：
   * `values`：在 `main` 函数的作用域中拥有**可修改权限**（如可以随时调用 `.push_back()`）。
   * `const_values`：在全生命周期中均被**强制锁定为只读**，任何试图修改它的操作都会在编译期报错。
