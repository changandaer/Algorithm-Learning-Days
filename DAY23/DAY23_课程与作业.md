### 2. 26：保留你的正确思路，不强迫换答案

你比较`nums[read - 1]`与`nums[read]`，看到新的值才写入前缀。这在这道有序数组题中正确。

为什么写入前缀没有破坏下一次相邻比较？写入位置不会超过当前read。如果写在read本身，值没变；如果写在更前面，当前read位置也没变。因此下一轮要比较的“上一项”仍是刚读过的原值，后面尚未读取的值也未被覆盖。

常见示范也可以比较当前值与最后一个已保留值，但那不是唯一正确写法。本课示范保留你的相邻比较。

你的注释把write说成“被替换次数”。更稳定的理解是：**已保留的不同值数量，也是下一个可写位置。** 比如`[1, 2, 3]`无需删掉任何重复值，最后write仍是3。你在283注释里的“下一个非零位置/非零数量”已经表达得更准确，不需要另背一个术语。

### 2. 283：你的原地实现已经正确

```python
class Solution:
    def moveZeroes(self, nums):
        write = 0
        for read in range(len(nums)):
            if nums[read] != 0:
                nums[write] = nums[read]
                write += 1

        for index in range(write, len(nums)):
            nums[index] = 0


solution = Solution()
nums = [0, 4, 0, -3, 4]
result = solution.moveZeroes(nums)
assert nums == [4, -3, 4, 0, 0]
assert result is None

nums = [0, 0]
solution.moveZeroes(nums)

nums = [-2, 5]
solution.moveZeroes(nums)

nums = [8, 0]
```

## 四、Python：从逐个找，走到一次排除半边

### 1. 为什么这次可以跳过没看过的数字

之前的数组题经常要逐个看。现在输入已经严格升序，例如：

```text
下标： 0   1   2   3   4   5   6
数值：-8  -2   1   4   9  15  21
```

找9时，如果查看中间的4，除了知道“4不是9”，还知道它左边的数都不超过4，因而也不可能是9。一次比较排除一整段，这就是**二分查找（binary search）**能变快的原因。

人话：不是凭感觉跳着找，而是用“这段绝不可能有答案”的理由，把候选范围缩小。没有有序性，这个理由就不成立。

### 2. 边界保存的是下标，不是数值

今天统一使用**闭区间（closed interval）**`[left, right]`：两端都还可能是答案。

- left是还要检查的最左下标；right是还要检查的最右下标。
- 全部数组的候选区间是0到`len(nums)-1`。
- left等于right时，还剩一个位置，不能当成已经找完。
- left大于right时，区间中没有位置了，才说明没有找到。

和昨天的write区分：write表示下一次放答案的位置；这里left/right只是记录“答案还可能在哪里”，不是移动元素，也不改原列表。

**中间位置（midpoint）**要用整数下标。Python的`/`返回浮点数，`//`向下取整；这里下标非负。例如下面只是演示算术，不是题目实现：

```python
print(9 / 2)   # 4.5
print(9 // 2)  # 4
left = 2
right = 7
mid = left + (right - left) // 2
print(mid)    # 4
```

`right-left`是两端的距离，取一半再加回left，就是当前区间中间位置。`(left+right)//2`在Python里也可以，不需要背两套写法。注意mid是下标，`nums[mid]`才是要拿来与target比较的值。[Python官方算术说明](https://docs.python.org/3/tutorial/introduction.html#numbers)

### 3. 区间怎样缩小才不会遗漏或卡住

用上面那组数组找9，观察一次完整过程：

| 当前候选下标 | 中间下标和值 | 有序性告诉我们什么 | 下一次候选 |
|---|---|---|---|
| 0—6 | 下标3，值4 | 下标0—3的值都小于9 | 4—6 |
| 4—6 | 下标5，值15 | 下标5—6的值都大于9 | 4—4 |
| 4—4 | 下标4，值9 | 命中目标 | 返回下标4 |

中间值偏小，下一段从mid的后一位开始；偏大，下一段在mid的前一位结束。**mid已经检查且不等于目标，应排除它。** 如果只把边界挪到mid，有些小区间不会变小，循环就可能一直重复。

命中目标时返回下标，结束这次函数。只有候选区间耗尽，才返回−1；不能第一次中间值不相等就认定全数组没有。

实现之前自己用`[2, 6]`找4推一遍：它明明处在最小值与最大值之间，却不一定在数组里。今天不提供完整循环或预填三步，让你把这个判断过程自己组织成代码。

### 4. 为什么时间不是O(n)

顺序找在最坏情况下要检查n项；二分每次保留大约一半。候选数量16→8→4→2→1，每增加一轮，能处理的数据规模大致翻倍，所以最坏时间为**O(log n)**，读作“对数级时间”。这里只需理解对半缩小，不背对数证明。

若用几个下标在原列表上查询，额外空间O(1)。如果每轮切片创建新的半张列表，就额外复制了数据；今天不要用切片递归，也不引入递归。

这个小示例可以独立编译，只说明三个操作；它没有完成今天“读入任意组数据”的作业：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values;
    std::cout << values.size() << "\n";
    values.push_back(4);
    values.push_back(7);
    std::cout << values.size() << "\n";
    return 0;
}
```

输出0、2，各占一行：

| 操作 | 盒子里有什么 | 返回或影响 |
|---|---|---|
| `std::vector<int> values;` | 空 | 建立容器 |
| `values.size()` | 不变 | 返回元素数量，开始为0 |
| `values.push_back(4)` | 4 | 把4放到末尾，长度变1；不返回新容器 |
| `values.push_back(7)` | 4、7 | 再追加7，长度变2 |

把第二个7换成−2，保存的是4、−2，长度仍为2。size数的是元素个数，不是把元素相加。push_back是直接改变原容器，不要把其结果赋回容器。

如果数据一开始就已知，也可以写`std::vector<int> values = {4, 7};`，花括号列出初始元素。今天作业要接收用户输入，不能用写死的示例数据代替读取。

### 3. 范围for：依次取元素，而不是自己管理下标

**范围for（range-based for）**适合“每个元素都处理一次”。下面的value直接是元素值，不是它的位置：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values = {4, 7};
    for (int value : values) {
        std::cout << value + 1 << "\n";
    }
    return 0;
}
```

输出5、8。冒号右边是要遍历的容器；左边声明本轮拿到的整数。这里只用`int value`按值取出，不改原容器。空容器没有元素，循环体一次也不执行。[范围for官方说明](https://learn.microsoft.com/en-us/cpp/cpp/range-based-for-statement-cpp?view=msvc-170)

普通for没有被淘汰：知道要读n次时，用已有的计数循环控制输入；数据保存好后，要把每个元素拿出来统计，范围for更直接。今日先不在遍历过程中追加或删除元素。

这是之前已有接触的内容。若你能直接解释两个示例，缩短阅读时间，把时间用在独立完成两题上，不强迫重听整节。

## 六、教材2.2.2：有了预测，怎样知道哪个模型更好

教材定位：[本地《神经网络与深度学习》](../../学习资料/AI%20agent/神经网络与深度学习%20%28邱锡鹏%29.pdf)，**书内26—29页，PDF阅读器41—44页**。重点是2.2.2的学习准则、公式(2.14)的平方损失、公式(2.22)的平均训练损失及过拟合。交叉熵、Hinge、正则化推导本轮暂不展开，不要求顺便背完本节所有公式。

### 1. 承接昨天：模型能表达答案，不代表现在的参数就是好答案

我们已经有四条样本：x为`[-1, 0, 1, 2]`，标签为`[-1, 1, 3, 5]`。昨天知道线性输出允许负数，而最后是ReLU的单神经元输出不了−1。

但允许输出负数还不够。线性模型设为w=1、b=0时，预测为`[-1, 0, 1, 2]`，只有第一条碰巧对；设为w=2、b=1时才与四条标签全部相同。

现在的问题从“能不能表达”变成了“这套参数目前错了多少”。只有四条数据可以靠眼睛看表，真实任务有成千上万条样本时，需要程序给出可比较的数字。这是引入**损失函数（loss function）**的直接原因：把预测与标签的差异转成一个数，当前任务里越小越好。

### 2. 为什么不简单地把带正负号的错误相加

用预测减标签得到**误差（error）**，正数表示预测偏高，负数表示偏低。方向有用，但直接平均会出问题。

假设两条标签都是1，模型分别预测0和2。误差是−1、+1，平均为0。模型两次都没猜对，怎么能说“平均错误为0，因此非常好”？因为偏高和偏低相互抵消了。

只统计对错也不够细：目标1，预测1.1和预测100都算“错一次”，无法区分距离有多远。我们需要既不让正负抵消，又能体现错得远近的度量。

### 3. 平方损失怎样满足这个需求

**平方损失（squared loss）**把误差平方。本课沿教材使用：

```text
单条损失 = (预测值 − 标签)² / 2
```

平方就是一个数乘它自己：−3的平方也是9。因此损失不为负，只有预测等于标签时为0。误差绝对值从1变2，平方从1变4，较大的偏差受到更重的惩罚。这也意味着异常的大错误可能影响很大，平方损失不是所有任务都必选的万能评分。

“除以2”是教材选用的固定系数，后面求导会更简洁；在当前只比较这个损失时，把所有候选都乘同一正系数不会改变谁最小，但会改变损失及梯度的数值。现在按这个约定算，不混用不同定义。

| 预测 | 标签 | 误差 | 平方 | 单条损失 |
|---:|---:|---:|---:|---:|
| 0 | 1 | −1 | 1 | 0.5 |
| 2 | 1 | 1 | 1 | 0.5 |
| −2 | 1 | −3 | 9 | 4.5 |
| −1 | −1 | 0 | 0 | 0 |

书中写标签减预测，本课写预测减标签；平方后相同。以后计算导数时必须与自己的完整表达式对应，不能只把中间负号随意换掉。

Python用`difference * difference`或`difference ** 2`表示平方，**不是**`difference ^ 2`。`**`是乘方，`^`不是；今天不需要研究后者。下面只示范一次数值运算，类的方法自己实现：

```python
difference = -3
print(difference * difference)      # 9
print((difference * difference) / 2)  # 4.5
```

### 4. 从一条损失到一组损失，为什么要平均

仍看线性模型w=1、b=0，逐行把“模型预测”送进刚才的评分规则：

| x | 标签y | 预测x | 预测−标签 | 单条损失 |
|---:|---:|---:|---:|---:|
| −1 | −1 | −1 | 0 | 0 |
| 0 | 1 | 0 | −1 | 0.5 |
| 1 | 3 | 1 | −2 | 2 |
| 2 | 5 | 2 | −3 | 4.5 |

四条相加是7，平均是`7/4=1.75`。如果只是把这四条原样复制一遍，总和会变14，平均仍是1.75。数据重复并没有让模型每条预测变得更糟；平均值帮助我们按“每条样本的错误大小”理解结果。

注意这是**先算每条的平方损失，再平均**，不是先平均带符号误差再平方。两者不能交换。

常见的**均方误差（mean squared error，MSE）**是不带1/2系数的平均平方误差。本课程使用“半均方误差”，即MSE的一半。上表MSE是3.5，课程平均损失是1.75。命名看起来相近时要看公式，不把软件里不同系数的数字直接混着比较。

### 5. 这就连接上了教材的“经验风险”

**经验风险（empirical risk）**是模型在已有训练样本上的平均损失。人话：拿手头这份练习卷，算平均扣了多少分。它不是一个新的、完全不同的计算；本课就是刚算出的1.75。

教材用N表示样本数，求和符号表示把每条损失加起来，前面的1/N表示再除以条数。模型参数θ在本课就是w、b；参数一变，预测改变，损失也随之改变：

| 模型 | 四个预测 | 本课平均损失 |
|---|---|---:|
| LinearNeuron(1, 0) | `[-1, 0, 1, 2]` | 1.75 |
| LinearNeuron(2, 1) | `[-1, 1, 3, 5]` | 0 |
| SingleNeuron(2, 1)，最后有ReLU | `[0, 1, 3, 5]` | 0.125 |

最后一行只有第一条错，单条损失0.5，除以4得到0.125。它比参数没选好的直线1.75更小，但仍比合适的直线0更大。**比较的是具体模型、具体参数在同一份数据上的结果，不是某种模型名字永远更厉害。**

到此能回答“现在谁的训练损失更小”，还不能回答“如何自动把参数改好”。计算出损失不会自己触发学习。

### 6. 为什么训练损失小，仍不能保证新题会做

真正关心的是没见过的数据。**期望风险（expected risk）**可以直觉理解为“按真实任务出现的各种情况及其概率计算的平均损失”；真实分布通常未知，所以不能直接把所有未来情况都算出来，只能用有限数据估计和检验。

想象两种规则：规则A使用`2*x+1`；规则B只记住这四个输入对应的标签，其余输入一律猜0。它们在这四条训练样本上的损失都可以为0，但输入3时，A给7，B给0。

这个例子不是让你写记忆表，而是说明：**只看训练表，无法确定谁学到了能推广的关系。** 模型把有限训练数据里的偶然细节、噪声也学得过头，导致新数据表现差，叫**过拟合（overfitting）**。训练损失0本身并不能单独证明过拟合；还要看未用于训练的数据表现。

因此DAY21的数据划分不是多余的形式：训练数据用于学习参数，验证数据用于选择设置，最终测试用于报告未参与选择的表现。看过测试结果后反复据此挑设置，就不能再把同一份测试当作完全独立的最终成绩。

教材图2.3对照欠拟合、正常拟合和过拟合。今天只理解“贴紧所有训练点不等于规律学得更好”，不要求实现正则化或另外训练多个网络。我们的四条数据是公开的人工小实验，不把在3、4上的检查包装成真实业务泛化成绩。

### 7. 为什么新增一个损失类，而不把所有事情塞进神经元

现在程序有三个不同职责，数据流如下：

```text
RegressionDataset给出(x, target)
             │
             ├── x → 模型.forward(x) → prediction
             │                            │
             └── target ─────────────────┤
                                          ↓
                       损失对象.forward(prediction, target)
                                          ↓
                                  一条样本的损失

一组对应的预测和标签 → 损失对象.mean(...) → 平均损失
```

模型负责“猜”，损失负责“评分”。同一把评分尺可以给线性模型、ReLU模型使用；不必在每种神经元里都重复实现评分规则。换评分方法也不必修改神经元如何计算预测。

这叫**职责分离（separation of responsibilities）**：不同部件负责不同计算。不是让你背设计模式，而是让这几段真实代码各有用途。普通函数也能算损失；此处用类把单条与平均两项相关操作组织在一起，方便后面与训练器组合，不声称只有类才能解决问题。

你的模型需要weight、bias长期保存，所以有实例属性。今天的SquaredLoss使用固定规则，不需要保存权重、标签或上次累计值，因此可以**不定义自己的`__init__`**，直接创建`SquaredLoss()`。不是每个类都必须人为添加状态。

方法仍有self：在mean方法里调用同一个损失对象的forward，可以用`self.forward(某个预测, 对应标签)`；这样单条评分规则只实现一次。平均计算中的累计量应在每次调用里重新开始，不带入上次结果。

今天结束后，已有“数据→预测→损失”。下节课才问“w稍微变一点，损失往哪个方向变”，引入变化率与导数；之后再用梯度下降更新参数。这就是损失为后续训练铺好的路。
