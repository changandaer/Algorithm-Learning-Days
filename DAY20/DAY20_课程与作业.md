### 1. 724：寻找数组的中心下标

```python
class Solution:
    def pivotIndex(self, nums):
        total = sum(nums)
        left_sum = 0
        for index in range(len(nums)):
            right_sum = total - left_sum - nums[index]
            if left_sum == right_sum:
                return index
            left_sum += nums[index]
        return -1


solution = Solution()
assert solution.pivotIndex([1, 7, 3, 6, 5, 6]) == 3
assert solution.pivotIndex([1, 2, 3]) == -1
assert solution.pivotIndex([2, 1, -1]) == 0
assert solution.pivotIndex([0, 0, 0]) == 0
assert solution.pivotIndex([8]) == 0
assert solution.pivotIndex([1, -1, 4]) == 2
assert solution.pivotIndex([-1, -1, 0, 1, 1, 0]) == 5
```

你的`adding`就是这里的`left_sum`，判断式也等价。示范多写`right_sum`，只是让左右两边更容易读，不代表你的表达式有错。

关键在于：检查下标`index`时，累计量只包含它左边的数。检查之后才把当前位置加入累计量，是为了给下一个位置使用。时间O(n)，额外空间O(1)；调用`sum`遍历一次，再遍历一次，仍是线性时间，不是平方时间。

### 2. 1480：一维数组的动态和

```python
class Solution:
    def runningSum(self, nums):
        result = []
        running_total = 0
        for value in nums:
            running_total += value
            result.append(running_total)
        return result


solution = Solution()
assert solution.runningSum([4, 1, -2, 3]) == [4, 5, 3, 6]
assert solution.runningSum([-2, -3]) == [-2, -5]
assert solution.runningSum([0]) == [0]
```

你使用下标读取元素，示范直接遍历元素，两种都正确。只需要元素时直接遍历稍短；需要位置时保留下标更合适，不必为了模仿示范改掉正确代码。

`running_total`保存“算到这里的总和”，`result`保存“每一步得到的总和”。这两个职责你已经写对。时间O(n)；输出列表占O(n)，除输出外的额外状态是O(1)。

### 5. 模型：EmbeddingTable

class EmbeddingTable:
    def __init__(self, vectors):
        self.vectors = vectors

    def forward(self, token):
        return self.vectors[token]

    def encode(self, tokens):
        result = []
        for token in tokens:
            result.append(self.forward(token))
        return result

### 6. 模型短练：你在注释里保留的神经元修正

下面给出完整参考，候选中保证有符合样本的权重。`fit`使用与`forward`一致的ReLU计算，选中后更新当前实例；这仍是候选搜索，不是反向传播。

```python
class SingleNeuron:
    def __init__(self, weight, bias):
        self.weight = weight
        self.bias = bias

    def forward(self, x):
        z = self.weight * x + self.bias
        if z > 0:
            return z
        return 0

    def fit(self, xs, ys, candidate_weights):
        for weight in candidate_weights:
            trial = SingleNeuron(weight, self.bias)
            predictions = []
            for x in xs:
                predictions.append(trial.forward(x))
            if predictions == ys:
                self.weight = weight
                return weight


neuron_a = SingleNeuron(0, 1)
neuron_b = SingleNeuron(0, 0)
xs = [0, 1, 2]
ys = [1, 3, 5]
candidates = [1, 2, 3]

assert neuron_a.fit(xs, ys, candidates) == 2
assert neuron_a.weight == 2
assert neuron_a.bias == 1
assert neuron_a.forward(3) == 7
assert neuron_b.fit([1, 2], [3, 6], candidates) == 3
assert neuron_b.forward(3) == 9
assert neuron_a.weight == 2
assert neuron_a.fit(xs, [1, 2, 3], candidates) == 1
assert neuron_a.forward(3) == 4
assert neuron_b.weight == 3
assert neuron_b.bias == 0
assert neuron_a.fit([-1, 0, 1], [0, 1, 3], candidates) == 2
assert neuron_a.forward(-1) == 0
assert neuron_a.forward(3) == 7
assert neuron_a.weight == 2
assert neuron_a.bias == 1
assert xs == [0, 1, 2]
assert ys == [1, 3, 5]
assert candidates == [1, 2, 3]
```

## 四、Python：从“生成新列表”走向“修改原列表”

### 1. 先分清这次到底要交付什么

1480允许返回一个新结果。344的要求不同：传进来的是**字符列表**，需要直接把这个列表倒过来，而不是另造一个倒序列表交回去。官方题目要求原地修改，额外空间O(1)。[LeetCode 344原题](https://leetcode.com/problems/reverse-string/)

**原地修改（in-place modification）**：改变调用方交给你的那个数据对象。人话就是：别人把一排卡片交给你，让你把这排卡片重新摆好，不是让你另外印一套，再把原来那排留着不动。

`"code"`是字符串；`["c", "o", "d", "e"]`是列表，列表里的每项恰好是一个单字符字符串。今天改的是列表位置，不是修改单个字符串内部的字符。

```python
letters = ["a", "b"]
letters[0] = "x"
assert letters == ["x", "b"]
```

给某个下标赋值会修改列表。相反，在函数内部仅把参数名改指向另一个新列表，调用方的原列表不会因此被替换。下面这个小实验只说明两种赋值的区别，不是344答案：

```python
def rebind(items):
    items = ["new"]


def replace_first(items):
    items[0] = "new"


values = ["old", "keep"]
rebind(values)
assert values == ["old", "keep"]
replace_first(values)
assert values == ["new", "keep"]
```

`items`可以理解为函数里用来找到列表的名字。给这个名字重新安排一个对象，和沿这个名字找到原列表、改它的一个位置，是两件事。[Python官方：列表](https://docs.python.org/3.11/tutorial/introduction.html#lists)

### 2. 交换为什么不能简单连续赋值

假设两张卡片写着7和9，想互换：先把7直接覆盖成9，原来的7就没地方找了。这也是下面代码失败的原因：

```python
a = 7
b = 9
a = b
b = a
assert (a, b) == (9, 9)
```

可以先用一个临时变量保留即将被覆盖的值：

```python
a = 7
b = 9
saved = a
a = b
b = saved
assert (a, b) == (9, 7)
```

Python也支持`a, b = b, a`：先求右边的两个原值，再分配到左边。今天两种写法都可以，不以“必须写得短”为目标。用于列表时，把这里的变量换成相应列表位置即可；你自己完成对应关系。

### 3. 两个位置标记怎样解决反转问题

**对撞双指针（opposite-end two pointers）**：用两个位置标记分别关注序列的两端，处理后向中间靠近。这里的“指针”只是两个整数下标，不是C++内存指针。

反转后，原先靠左的位置对应靠右的位置。因此可以成对安置卡片，而不是为每个位置再找一遍目标。已经安置好的外侧位置不再需要处理，尚未处理的范围逐渐缩小。

需要你理解而不是背循环的两个问题：

- 长度为5时，中间那一项是否需要和另一项交换？
- 两个位置相遇或错开以后还继续处理，会不会把之前的结果换回去？

用5张纸写`a、b、c、d、e`试一下，再自己确定起始位置、停止条件和每次位置的变化。这里不替你写作业的三步分析，也不提前给完整循环。

可以复用DAY04已学的Python `while`：每次先检查条件，成立才运行缩进内的代码；本轮结束后再检查。现在决定是否继续的不是“成绩是否有效”，而是你定义的未处理范围是否还需要处理。由你自己写出条件与位置更新。

**复杂度**：成对交换的次数大约是长度的一半，因此时间O(n)。位置标记和临时变量的数量不会随列表变长而增多，因此额外空间O(1)。本题已有输入列表的空间不算你新申请的额外空间。

## 五、C++：把重复做的事交给for循环

### 1. 为什么需要循环

昨天你的程序读入一次数据，判断一次。现在需要处理一段连续整数：范围可能长也可能短，不适合手写几十行相同输出。

**循环（loop）**就是在条件满足期间重复执行同一段代码。普通`for`把“从哪里开始”“什么时候继续”“做完一次怎样前进”集中写在一个地方。

下面只演示从2开始每次增加2，不是今天两题的完整解答：

```cpp
#include <iostream>

int main() {
    for (int value = 2; value < 8; value = value + 2) {
        std::cout << value << '\n';
    }
    return 0;
}
```

输出依次为2、4、6。三个位置的职责：

| 位置 | 示例 | 什么时候执行 |
|---|---|---|
| 初始化 | `int value = 2` | 开始前执行一次 |
| 继续条件 | `value < 8` | 每次进入循环体之前检查，包括第一次 |
| 更新 | `value = value + 2` | 本轮循环体执行完，再执行 |

真实顺序是：先初始化；检查成立就运行花括号里的语句；更新；再次检查。不是三个位置从左到右都执行后才输出。到了8时，条件已经不成立，因此不输出8。[C++ for语句说明](https://learn.microsoft.com/en-us/cpp/cpp/for-statement-cpp?view=msvc-170)

本课用`value = value + 1`表示增加1就够了。你以后看到`++value`，它也能表达增加1；这次不要求学习它在复杂表达式里的用法。

### 2. 把昨天的判断放入循环，才会产生筛选

“每个数都看一遍”和“每个数都加入总和”不是同一句话。循环负责逐个访问；`if`决定当前这一项要不要参与计算。

**累计量（accumulator）**就是到目前为止的部分结果。它应该在处理整段范围之前初始化。如果每一轮都重新设为0，你留下的就不是整段的累计结果。这个道理与你的Python动态和完全相同，只是C++要声明类型。

初始化写在`for`里的`value`只在这个循环范围内使用；若循环后仍要输出总和，应把总和变量放在循环外声明。这里是在实际程序里使用局部变量，不额外引入一套记忆规则。

容易影响核心结果的两件事：

- 上界要包含时，`<`与`<=`的结果不同。
- 忘记让位置变化，条件可能一直成立，程序不断输出；可以在终端按Control+C停止，再检查更新部分。

不要在`for (...)`后多放一个分号；循环体是后面的花括号，不是一个空语句。

## 六、教材与模型：Embedding不是终点，它是预测系统的入口

今天核对的是[本地邱锡鹏教材](../../学习资料/AI%20agent/神经网络与深度学习%20%28邱锡鹏%29.pdf)**1.4—1.8，书内10—20页，对应PDF阅读器25—35页**；开头补连1.3的输入表示。教材用于确定概念与章节关系，下面的数值例子是为你重新设计的，不是书中原文。历史、流派与框架概览用于解释“为什么走到这里”，不要求背年份或工具名单。

### 1. 先有一个任务，才知道表示好不好

我们只考虑一个极小任务：输入“猫”“狗”或“车”，想输出一个分数，猫和狗的目标分数为1，车为0。它仅用于演示计算和学习，不是现实世界完整的分类系统，也不需要概率知识。

你昨天写了一个表，输入“猫”就输出一串数字。但如果没有说清这串数字接着干什么，查表确实像一件没有目的的事情。我们先把整体关系摆出来：

```text
类别“猫” → 取出它的向量 → 神经网络计算 → 预测分数
                                             ↓ 与目标分数比较
                               训练时根据差异调整表和网络参数
```

上面从左往右算结果，叫**前向计算（forward computation）**；根据样本调整参数属于**学习或训练（learning / training）**。你昨天主要写了第一段：取向量。取向量不等于整条预测，更不等于下面的参数调整。

### 2. 在可学习向量之前，问题可以怎样解决

对只有三个固定类别的小任务，人工写规则就能做对。我们不需要为了显得高级而强行训练模型。但词的种类很多、输入换成整句话、任务改变时，手写规则和手工设计特征会越来越费力，也可能遗漏重要联系。

一种简单办法是编号：猫1、狗2、车3。**编号（ID）解决的是“认出谁是谁”，不是“谁和谁意思相近”。** 如果直接把编号当数量输入一个神经元，模型会按大小、距离计算；而换一种编号顺序不该改变类别本身的含义。

所以可以用**独热表示（one-hot representation）**：三个位置分别代表三个类别，猫`[1,0,0]`、狗`[0,1,0]`、车`[0,0,1]`。它避开了把任意编号顺序误当成大小关系的问题，也允许后面的模型为不同类别学习不同作用。

但这三个编码本身没有表达“猫和狗在某个任务上更相似”。类别很多时，向量宽度也随类别数量增加。实际系统可以稀疏存储one-hot，不一定真的创建一大排0；所以不能把它简单说成“一定浪费内存、不能学习”。真正要问的是：能不能学出一种方便后续模型共享信息的表示，而不只给每个类别一个孤立身份？

过去及现在也有手工特征、词频/共现统计等路线。例如观察哪些词经常出现在相似上下文，再压缩统计信息。可学习的神经向量不是凭空跳出来的唯一办法，也没有让所有旧方法失去用途。

### 3. Embedding的改动：让表示本身也能被调整

**嵌入表示（embedding）**把离散类别映射成固定长度的数值向量。在神经网络里，常见实现是一张可训练的表：每个类别一行，每行D个数。

人话：以前给类别发一张固定的身份证；现在给它一张可以根据任务不断修改的“数值说明卡”，交给后面的模型使用。说明卡不一定能被人逐栏命名，它的好坏要看是否帮助模型完成任务。

假设有V个类别，每条向量D维，表中共有V×D个数。一条输入取出的表示可以比one-hot短，但整张表仍然要保存，不是“使用Embedding以后就不占空间了”。

你的`self.vectors`就是这种表的教学实现；`forward("猫")`是取出猫所在的一行。真实系统常先把词转成编号，用编号定位表中的行；编号负责定位，行里的浮点数才是供网络计算的表示。

one-hot和查表也不是彼此毫无关系：one-hot中只有一个位置为1，用它去选择参数表时，效果就是取出对应的一行。今天先理解“选哪行”即可，矩阵乘法到数学阶段再完整手算。

### 4. 那些数到底从哪里来？先把一个学习过程走通

常见做法是：确定类别表和维数，用小随机数初始化，或者采用已有模型学好的向量。**初始化**只是给训练一个起点，不代表已经有语义。接着把向量送入后面的预测模型，比较预测与样本目标，再调整有关参数。

我们用你在DAY18已会的“尝试候选参数”演示这件事，不突然引入求导公式。为方便手算，每个类别的向量只有一项，记作`[e]`；后面固定接一个神经元，计算`ReLU(2×e)`。

ReLU仍是已学的“负数变0，非负数保持”。先有一张人为设置的初始表：

| 类别 | 初始e | 神经元输出 | 目标 |
|---|---:|---:|---:|
| 猫 | 0.2 | 0.4 | 1 |
| 狗 | 0.1 | 0.2 | 1 |
| 车 | 0.3 | 0.6 | 0 |

现在的问题不在“查错行”，而在“行里的值不适合这个预测任务”。固定神经元参数，只尝试改变表里的值：

| 类别 | 尝试的e | 相应输出 | 这次选中的e |
|---|---|---|---:|
| 猫 | 0.2、0.5、0.8 | 0.4、1、1.6 | 0.5 |
| 狗 | 0.1、0.5、0.9 | 0.2、1、1.8 | 0.5 |
| 车 | 0.3、0、0.4 | 0.6、0、0.8 | 0 |

于是表可以更新为猫`[0.5]`、狗`[0.5]`、车`[0]`。再经过同一个神经元，恰好得到1、1、0。

这里连接了三件事：**向量参与预测；样本告诉我们预测是否符合目标；依据结果选一个更合适的向量值。** 数值来自这个学习过程，不是模型先懂了“猫的含义”再把含义翻译成0.5。

这个手算例子中，猫和狗变成同一个向量，是因为任务只要求区分它们与车，不要求区分猫和狗。换成“判断是猫还是狗”的任务，这个表示就不够用了。因此不要背“Embedding一定使猫狗靠近”，更不能认为每一维必然对应人能命名的一个特征。

这是一段有限候选学习的说明，不是要求你今天再写一个Embedding训练器，也不是反向传播。真实模型参数多，穷举候选通常不可行；后面DAY23—DAY27会依次讲损失、导数和梯度下降，解决“怎样更有效地调整参数”。本轮先在简单线性模型上把这条训练流程做通，不承诺本周已经能训练语言模型。

### 5. 没有人给每个词写“含义答案”，语言向量还能学吗

可以把任务设为“根据前面的词预测后面的词”。文本自身就能提供这种训练样本：输入来自一部分文本，目标来自随后出现的词。模型预测不好，就按训练规则调整参数；其中也可以包括输入向量。

如果一些词经常出现在相似环境中，训练可能让它们获得对这个预测任务有用的相似表示。但这是训练数据与目标共同作用的结果，不是查表操作自带的语义魔法。不同数据和目标可能学出不同表示，也会保留偏差和局限。

补一个真实历史定位，避免把上面的教学推演误说成发明史：早期LSA利用词与文档统计及降维构造表示；Bengio等人在2003年的神经概率语言模型中联合学习词的分布式表示和预测函数；2013年的word2vec进一步研究了大规模学习词向量的高效方法。Embedding没有一个适用于所有领域的“唯一发明时刻”，不是先出现某一张字典才突然被创造出来。[LSA原始论文](https://asistdl.onlinelibrary.wiley.com/doi/10.1002/%28SICI%291097-4571%28199009%2941%3A6%3C391%3A%3AAID-ASI1%3E3.0.CO%3B2-9)、[Bengio等，2003](https://jmlr.org/papers/v3/bengio03a.html)、[word2vec论文，2013](https://arxiv.org/abs/1301.3781)

历史是补充阅读，不要求记年份。今天要理解的是：**类别身份 → 可调整的向量 → 完成任务的预测 → 训练反馈调整向量**。

### 6. 有了Embedding，为什么还需要后面的网络

查出的向量通常只是输入表示。上面的例子必须再经过`ReLU(2×e)`才能得到任务分数；换一个预测器，原来的表未必还能输出正确结果。

对语言来说，一张固定表对同一个词总取出同一行。例如“苹果”的固定向量不会因为这次句子谈水果还是公司，就自行变换。需要后续网络结合周围输入计算，形成与当前上下文有关的表示。

这为未来的Transformer留下了明确问题：不只是“怎样查到一个词的向量”，还要“怎样结合其他词来理解它在这一次输入里的作用”。原始Transformer将嵌入表示作为输入处理的一部分，再通过注意力等部件进行计算；今天不提前教注意力公式。[Transformer原始论文](https://arxiv.org/abs/1706.03762)

所以学习顺序不是“背Embedding，背网络，背Transformer”，而是：先让离散输入成为能计算的数值表示，再学习怎样组合计算，随后学习怎样让整个系统根据数据改变。

## 七、从一个神经元到小网络：教材1.4—1.8怎样接在上文后面

### 1. 一个部件的输出，可以成为另一个部件的输入

**前馈神经网络（feedforward neural network）**把计算部件按输入到输出的方向连接起来。人话：第一道加工的结果交给第二道加工，而不是每个部件各算各的，最后互不相干。

先不引入多输入和矩阵。我们用两个已会的单输入ReLU神经元，定义网络A：

- 第一个：权重2、偏置1，得到中间结果`h = ReLU(2×x + 1)`。
- 第二个：权重−1、偏置4，把h作为输入，得到`y = ReLU(−h + 4)`。

`h`是**中间表示或隐藏表示（hidden representation）**。人话就是“第一道处理之后，第二道处理之前的那个数”，不是神秘的另一个模型参数。

手算`x=1`：第一次加权和是3，ReLU后h仍为3；第二次加权和是1，ReLU后输出1。第二个神经元读的是h，不是重新读原来的x。

再看`x=-1`：第一次加权和−1，被ReLU截为0；第二次用0计算，得到4。负数分支让你能检查自己是否真的把两道计算接起来。

### 2. 为什么层数和非线性要放在一起理解

**深度（depth）**关注输入到输出经过多少层连续变换，不是代码文件有多少行。层数怎样计数可能因约定而异；今天只说“两个神经元串联的极小网络”，不把它包装成完整深度学习系统。

如果去掉两处ReLU，上面的计算会变成：

`h = 2×x + 1`

`y = −h + 4 = −(2×x + 1) + 4 = −2×x + 3`

虽然写了两层，仍然能合并成一条直线。加入ReLU后，输入落在不同区间时，计算会出现不同的分段行为。例如x=−1时，带ReLU的网络输出4，而合并出的直线输出5，二者不是同一个函数。

这说明**非线性（nonlinearity）**不是给公式装饰一个名字，而是让组合能表达单一线性变换做不到的关系。更宽、更深的网络能够形成更丰富的组合，但“不停加层就一定更好”不成立：还需要数据、合适的训练方法及验证。

### 3. 这与人工神经网络、端到端学习是什么关系

教材1.5讲人工神经网络，是为了说明我们怎样用许多简单计算单元和连接构造可学习的函数。它受到生物神经系统启发，但不能把一个Python类等同于对真实大脑的精确模拟。网络发展的实际困难不只有“会不会接线”，还包括如何学习参数、是否有足够数据和计算资源；历史阶段在这里帮助解释这些条件，不要求你背年表。

**端到端学习（end-to-end learning）**是让从输入到任务输出的可学习部件，围绕最终任务目标一起调整。例如根据最后的预测误差，训练规则既可能调整后面神经元的权重，也可能调整前面的Embedding表。

人话：不只是每道工序各自看起来正常，而是拿最终成品是否合格来改进整条加工过程。但这不意味着人不再选择结构、数据和目标，也不意味着每一个部件都必须可训练。

你今天写出`Embedding → 神经元1 → 神经元2`，只是连通了前向计算。**没有利用样本调整参数，就不能说完成了端到端学习。** 类叫Network、方法叫forward，也不会自动产生训练。

### 4. Python面向对象现在解决什么实际问题

如果每新增一个网络都把神经元公式再粘贴一遍，就难以复用已验证的部件。我们希望新网络保存两个已有神经元对象，让它们各自完成自己的计算。

**对象组合（object composition）**：一个对象把其他对象保存为自己的组成部分，并调用它们协作。人话：网络里面“装着”两个神经元，不是网络“继承成为”神经元。今天不学继承。

在`TinyNetwork`中：

- `self.first`保存第一个神经元对象，不是第一个权重数字。
- `self.second`保存第二个神经元对象。
- 这些神经元仍各自拥有`weight`和`bias`。
- 本次输入x和中间结果h在这次`forward`里使用，不必为了持久保存而都塞进实例属性。

表达式`self.first.forward(x)`的意思是：找到当前网络保存的第一个对象，让这个对象使用它自己的参数处理x。它不是重新创建一个神经元，也没有复制一份权重。你已经在候选模型代码里调用过别的对象，现在只是把这种合作长期组织在一个网络对象里。

所有部件都叫`forward`，是因为它们都提供“拿输入算输出”的**接口（interface）**；但接口名字一样，不代表输入形式一定一样。昨天Embedding输出两项列表，而目前SingleNeuron接收一个数，不能直接硬接。

今天采用明确的一维表示`[e]`做最小连接实验。取它的第0项就得到了整个一维表示的那个数；**不是把昨天二维向量随便丢掉一半**。未来学多输入神经元后，才让网络完整接收多维向量。

### 5. 作业04：从Embedding到神经元组合

文件：[04_模型实践_从Embedding到神经元组合.py](04_模型实践_从Embedding到神经元组合.py)

旧部件允许复用你已经理解的`SingleNeuron`和`EmbeddingTable`定义，只带类定义，不必复制昨天整段测试；无需新学跨文件导入。今天从空白写的是`TinyNetwork`及连接测试，不重新抄一套旧类凑代码量。

接口要求：

- `TinyNetwork(first, second)`接收两个已经创建好的神经元对象，分别保存为`self.first`、`self.second`。

- 调用只做预测，不改变神经元的权重和偏置。
- 不写fit，不加入继承、装饰器、NumPy或PyTorch。

先创建上面定义的网络A，并核对中间结果与输出。可以在自己的测试中单独调用第一个神经元检查h，不需要为了测试新增一套网络接口。

| 输入x | 第一段h | 网络A输出 |
|---|---:|---:|
| −2 | 0 | 4 |
| −1 | 0 | 4 |
| 0 | 1 | 3 |
| 1 | 3 | 1 |
| 2 | 5 | 0 |

再用两只新神经元创建网络B：第一只权重1、偏置0；第二只权重2、偏置1。B在输入−1、0、1时，应分别输出1、1、3。之后再次调用A，输入1仍应输出1；不要让两个网络不小心共用本来应该不同的神经元对象。

最后用刚才候选学习示意中的一维表：猫`[0.5]`、狗`[0.5]`、车`[0.0]`。先查向量，取唯一的那一项，交给网络A。由你自己把已经学过的调用串起来：

| 类别 | 取出的向量 | 网络A的最终结果 |
|---|---|---:|
| 猫 | `[0.5]` | 2 |
| 狗 | `[0.5]` | 2 |
| 车 | `[0.0]` | 3 |

**为什么这里不是目标1、1、0？** 前面选择这张表时，预测器是`ReLU(2×e)`；现在换成了网络A。表与旧预测器配合得好，不代表换一个预测器后结果仍正确。这个实验刻意让你看见：查表、正确执行网络、完成任务，分别需要不同证据。这里验证的是连接和计算，尚未训练新网络；不能把输出2、2、3写成“分类成功”。

规定数值都可以准确核对，今天不额外增加浮点容差教学。自己写三步分析、调用和断言。若卡住，发你已经写到的部分，我先给引导，不提前给完整TinyNetwork答案。
