## 2. 哪一个重载？

`split_views(source)`、`split_views(source,2)`、`split_views(source,4)` 各调用哪个版本？运行时把 `parts` 从 2 改成 4，`split_views(source,parts)` 的参数数量是否改变？

我的回答：`split_views(source)`调用单参数的函数、`split_views(source,2)`和`split_views(source,4)`调用两个参数的函数，
运行时把 `parts` 从 2 改成 4，`split_views(source,parts)` 的参数数量不会改变，参数数量是定义函数时预先确定的

## 3. 为什么会歧义？

同时声明一参数版和第二项带默认值 `=4` 的两参数版时，为什么 `split_views(source)` 难以选择？只改变返回类型为什么也不能解决？

我的回答：因为 `split_views(source)`既符合一个参数版也符合带默认值的两参数版，选择重载函数只与函数的参数个数、类型、顺序有关

## 4. 从 ROS 接口读到 C++ 调用

`monoImageCallback` 收到的 `image` 是什么类型，因此 `getImageFromMsg(image)` 选中哪个声明？消息的 `encoding` 从 `mono8` 改为 `mono16`，会改变这条调用的重载选择吗？

我的回答：`monoImageCallback` 收到的 `image` 是sensor_msgs 中的 ImageConstPtr 这个智能指针类型，
因此 `getImageFromMsg(image)`选中cv_bridge::CvImagePtr getImageFromMsg(const sensor_msgs::ImageConstPtr &img_msg);
消息的 `encoding` 从 `mono8` 改为 `mono16`，不会改变这条调用的重载选择，传入参数的类型决定使用哪个重载，已经进入这份实现后，程序才读取 `encoding` 字段
