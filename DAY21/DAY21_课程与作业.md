class Solution:
    def reverseString(self, s):
        left = 0
        right = len(s) - 1
        while left < right:
            s[left], s[right] = s[right], s[left]
            left += 1
            right -= 1

### 2. 724：寻找中心下标

```python
class Solution:
    def pivotIndex(self, nums):
        total = sum(nums)
        left_sum = 0
        for index in range(len(nums)):
            if left_sum == total - left_sum - nums[index]:
                return index
            left_sum += nums[index]
        return -1


solution = Solution()
assert solution.pivotIndex([2, 4, 1, 6]) == 2
assert solution.pivotIndex([1, 2]) == -1
assert solution.pivotIndex([0, 0]) == 0
assert solution.pivotIndex([2]) == 0
```

你的代码计算正确。`right_side`实际上装的是当前位置左侧已经累加的和，叫`left_sum`更容易解释，但这是可读性建议，不是逻辑错误。你从左向右检查并立即返回，也保证找到最左侧答案。时间O(n)，额外空间O(1)。

## 四、Python新内容：两个位置可以分工，而不一定从两端出发

### 1. 先明确283要完成的变化

新题是简单题[283移动零](https://leetcode.com/problems/move-zeroes/)：把所有0放在整数列表末尾，**保留非零元素原来的相对顺序**，在原列表上修改，不另造一份数组。

例如`[0, 5, 0, -2, 5]`变成`[5, -2, 5, 0, 0]`。两个5都要保留，−2也不是0，不能删掉。这里没有去重，没有排序，也没有缩短列表。

**相对顺序（relative order）**指先遇到的非零数，整理后仍排在后遇到的非零数前面。就像排队的人里有空位，可以让人靠前站，但不能趁机把后面的人调到前面。

昨天反转是有意颠倒顺序；今天移动零要保留非零顺序。两题都用位置标记，但不能把昨天“左右两端交换”的循环原封不动照搬。

### 2. 读位置与写位置分别关心什么

**读写双指针（read/write pointers）**用两个整数下标表达两种进度：一个关注“目前看到哪里”，另一个关注“下一个保留的元素应该放在哪里”。这里仍不是C++内存指针。

先用一个局部场景理解，不直接给283整题步骤：一排卡片中，前面有一个空位，后面读到一张需要保留的B卡。读位置在B那里，写位置在空位那里，二者不必相同。把B的内容写到空位后，“看过多少张卡”和“已安置多少张卡”显然是两个数量。

你要理解的不是两个变量必须叫什么，而是：

- 每看过一个位置，阅读进度就变化；但不一定每次都产生一个要保留的元素。
- 已经安置好的前面一段应保持正确顺序；还没整理的后面一段暂时不能当作最终结果。
- 写入时不能破坏尚未读取的有效数据。让写的位置不超过读的位置，是一种容易检查的安全关系。

**前缀（prefix）**就是列表开头连续的一段，例如`[5, -2]`可以是某个结果列表已经整理好的前缀。前缀正确不意味着整张列表已经正确：剩余位置还必须满足本题对0和长度的要求。

### 3. 会修改一个位置，怎样组合成算法

已学的`nums[index] = value`会覆盖原列表某个位置；它不会插入一个新位置，也不会自动清除被读取位置的旧值。`len(nums)`则不会因这种覆盖而变化。

例如下面只演示覆盖行为，不是移动零解法：

```python
cards = [8, 0, 6]
cards[1] = cards[2]
assert cards == [8, 6, 6]
assert len(cards) == 3
```

看见两个6不说明赋值没执行；它说明“复制一个值”不是“把源位置自动清空”。你需要自己决定一题的最终状态应是什么，而不能假设某个操作会替你做未写出的工作。

逐个删除元素或插入元素会改变后续下标，还可能反复搬动很多项。今天优先用已学的下标赋值或交换，不用删除、插入、排序、新结果列表或列表推导式绕过练习目标。

目标复杂度是O(n)时间、O(1)额外空间。哪怕有两个先后执行的线性循环，也不一定是O(n²)；关键看总共处理了多少次元素，而不是数代码里有几个`for`。若每看一个元素都重新扫描整段，才可能变成平方级。

## 五、C++：条件决定何时继续，break决定何时离开

### 1. 为什么有了for，还要学习while

昨天你知道起止范围，适合把起点、条件、更新写在for头部。今天第二题会一直读取数字，不预先知道用户输入多少个，只知道遇到0结束。这时用条件循环更直接。

**while循环**在每一轮开始前检查条件，成立就执行花括号中的代码，执行完再检查。第一次条件就不成立时，一次也不执行。它与Python while的思路相同，只是C++要写括号、花括号和分号。[C++ while说明](https://learn.microsoft.com/en-us/cpp/cpp/while-statement-cpp?view=msvc-170)

用一个与作业不同的小例子看它怎样前进：

```cpp
#include <iostream>

int main() {
    int value = 1;
    while (value < 10) {
        std::cout << value << '\n';
        value = value * 2;
    }
    return 0;
}
```

输出1、2、4、8，每项一行。更新成16后，下一次检查不通过，所以16不输出。初始值、继续条件和状态更新仍然存在，只是不再集中写在for的三个位置里。

如果忘了更新value，它会一直等于1，条件永远成立。程序不断输出时按Control+C停止，然后检查是什么状态应当变化。`while (...)`后面也不要多写一个分号。

### 2. break不是“结束整个程序”

**break语句**退出当前所在的最内层循环，然后继续执行循环后面的代码。人话：离开这次重复过程，不是把整份程序关掉。它也不是仅跳过一行。[C++ break说明](https://learn.microsoft.com/en-us/cpp/cpp/break-statement-cpp?view=msvc-170)

```cpp
#include <iostream>

int main() {
    for (int value = 1; value <= 6; value = value + 1) {
        if (value == 4) {
            break;
        }
        std::cout << value << '\n';
    }
    std::cout << 99 << '\n';
    return 0;
}
```

输出1、2、3、99。检查到4时跳出循环，所以不输出4；循环之后的99仍然输出。`return 0;`则是离开main，不能拿它随意替换这里的break，否则循环后的输出也执行不到。

`while (true)`表示条件始终成立；C++写小写`true`，不是Python的`True`。它可以与循环内部的break配合表达“不断处理，直到内部检测到结束信号”。这不是要求你无条件写死循环，而是把结束判断放在读到新数据之后。

### 3. 连续输入时，为什么每轮都要得到新值

`std::cin >> value`只读取这一次的一个整数，不会因为外面有循环就自动更新所有未来输入。要处理下一项，就得让程序再次执行读取。

**哨兵值（sentinel value）**是事先约定的结束标记，今天使用0。这里0表示“停止收集”，不表示有一个需要预测或统计的新样本。负数仍是正常数据，不得把所有小于等于0的数都当成停止标记。

例如输入`3 -2 0 100`，遇到0就停止，之后的100不属于这次任务；最终应得到1。输入可以同一行用空格分开，也可以每行一个，`cin`都能逐项读取。输入完普通数字但还没输入0时，程序继续等待是正常的，不一定是卡死。

今天保证输入都是合法整数，最终会出现0，序列不超过100项、每项在−100到100之间。不加EOF、格式错误恢复或异常处理，先掌握循环本身。

## 六、教材2.1：模型已经会计算，为什么还需要“样本”和“数据集”

参考[本地《神经网络与深度学习》](../../学习资料/AI%20agent/神经网络与深度学习%20%28邱锡鹏%29.pdf)第2.1节：**书内23—24页，PDF阅读器38—39页**，包括公式(2.1)—(2.4)和图2.2。已核对正文及图。今天不要求概率推导，不提前学习2.2的完整模型、损失、优化理论。

### 1. 承接昨天：只有预测值，不能知道预测好不好

昨天输入“猫”，查到向量，经过网络得到2。程序完全可能按公式算对，却没有完成目标分数应为1的任务。因为“程序运行正确”和“预测符合目标”是两种检查。

你已经说清了没有用样本优化参数就没有训练。接下来必须补齐的是：模型到底拿到什么样的样本，凭什么知道预测应该接近谁？这就是教材2.1放在学习算法之前的原因。

一次学习用的记录不能只有输入，还要有相应的目标。昨天的例子可以记为“猫→1、狗→1、车→0”。前者决定给模型什么信息，后者决定我们希望它学会什么关系。

**特征（feature）**是用于预测的输入信息；**标签或目标值（label / target）**是在监督学习中拿来对照的答案；一份配对的输入与答案构成这里的一个**有标签样本（labeled sample）**。并不是所有机器学习数据都有标签，今天专注于有标签的情形。

人话：特征是题目给你的线索，标签是这道题的参考答案，样本是题目与答案配成的一条记录。你可以根据答案批改预测，但不能把答案冒充预测时本来就知道的线索。

### 2. 为了最终真正训练，先把例子缩到一个数

本轮约定的最终作品是学会一条数值关系的线性神经元，不是十天内训练语言模型。因此从今天起，用同一组人工数据贯穿后面的模型、损失和优化。我们把类别表示这一步暂时省掉，只保留一个已经是数字的输入x。

| 样本位置 | 输入x | 目标y |
|---|---:|---:|
| 0 | −1 | −1 |
| 1 | 0 | 1 |
| 2 | 1 | 3 |
| 3 | 2 | 5 |

这四条数据由我们按`y = 2×x + 1`构造，关系是已知的，便于核验实验。以后训练程序仍要依据这些样本更新参数，不能把答案公式硬编码进训练过程，然后宣布“学会了”。它也不代表真实数据永远没有噪声。

四个输入可以保存为`xs = [-1, 0, 1, 2]`，四个目标保存为`ys = [-1, 1, 3, 5]`。**相同下标表示同一条记录**。例如下标2对应输入1与目标3，不能误配成输入1与目标1。

这里有4个样本，每个样本只有1个数值特征。不要把“列表里有4个输入”理解为“一个样本有4维”。如果以后每个样本同时包含长度、宽度两个数，那才是每个样本2维。

预测连续数值的任务叫**回归（regression）**；判断离散类别的任务叫分类。这里的“回归”不是把数倒回去，而是预测一个数量。标签可以是负数或小数，不要求只能是0、1；这与输入是Python整数还是浮点数不是同一个分类标准。

### 3. 用教材符号把数据与代码对上，不背抽象公式

教材公式(2.1)把数据集写成若干对`(x, y)`的集合，N表示样本个数，D表示每条输入的特征维数。上面就是N=4、D=1。

符号`x^(i)`中的上标在这里表示“第i个样本”，不是x的i次方。书上通常从第1个样本编号，Python下标从0开始；写代码时按你的列表下标对应即可。

公式(2.2)中的`ŷ = f(x)`可以读成“模型拿x计算出预测值”。`ŷ`读作y-hat，帽子提醒你它是预测；`y`是数据提供的目标。对应到代码，就是已有的`model.forward(x)`返回一个预测数字，而不是自动返回数据标签。

例如固定使用你已实现的`SingleNeuron(2, 1)`，在x=−1时它输出0，因为ReLU截掉了负数；但样本目标是−1。此时数据没有取错，程序也可能没有算错，只是这种模型的输出形式没有给出这个目标。今天先把差异观察出来，DAY22再用线性输出与ReLU模型对照解释。

### 4. 为什么不能把所有见过的数据都拿来证明“学会了”

一组样本就是**数据集（dataset）**。需要学习时，一部分数据用于调整模型，叫**训练集（training set）**；另一些不参与这次调整的数据用于检查新样本上的表现，叫**测试集（test set）**。

人话：练习册上的题可以反复参考答案改正；想知道是否学会，还要做没有用来练习的新题。如果把刚背过的题直接当作独立考试，就分不清真正理解与记住答案。

本轮用上面四条记录演示训练数据，另用x为3、4，目标为7、9的两条记录演示测试数据。将它们存到两个独立的数据集对象里，便于以后控制哪些数据进入训练。

但是变量叫`test`并不会自动保证公正：如果反复根据所谓测试结果选择结构和参数，这批数据就已参与开发。正式项目通常还会用**验证集（validation set）**做开发选择，最后保留独立测试集。本课只解释作用，不要求你立刻实现三种拆分工具。

今天这六条都是公开的人工检查数据，只用于演示数据流，不能据此宣称真实泛化能力。手工把权重设为2、偏置设为1，也不能称为“从训练集学出参数”。

**泛化（generalization）**就是模型对未用于学习的新样本也有用。教材提到**独立同分布（IID）**，大意是样本的抽取相互独立，来自同一种数据分布。实际数据不一定满足：重复拍同一个对象的近似照片，不能简单视为互不相关的新证据；部署场景改变，测试结论也可能失效。今天只建立这个警觉，不学习概率证明，也不把六个手选数字冒充随机IID实验。

### 5. 标签到底怎么使用，才没有把答案偷偷喂给模型

预测时，我们希望得到的是`model.forward(x)`。标签y另行保存，用来与预测对照；不是为了让结果正确，就调用模型时把y直接当x传进去。

以后训练时，y当然会参与误差计算和参数更新，这正是监督学习的监督信号；但它不因此变成这条记录的预测输入。新样本实际到来时，通常正是因为不知道y，才需要模型预测。

这也补上昨天Embedding的问题：表里的值要根据任务反馈调整，反馈从预测与目标的比较而来。只给表重复查询同一输入，不会凭空产生改进信号。

教材图2.2把训练数据、学习算法、模型的选择与预测联系起来。今天完成的是其中的数据供应和预测观察，还没有实现学习算法。公式(2.4)展示分类准确率，可理解为“预测正确的条数÷测试总条数”；本轮是数值回归，不把严格相等的比例当作主要效果指标，DAY23会用损失描述预测相差多少。代码中的精确断言只是检查这些已知整数运算有没有算错。

## 七、模型实践：只新增一个负责取样的类，交付说明写清楚

### 1. 为什么不是随便再练一个类

现在有两份对应列表xs与ys。代码散落到各处时，很容易取错下标或把输入和目标配错。我们要把“保存这批数据”和“按同一个下标取出一对记录”放在一起。
