### 00：LC387，第一个唯一字符

```python
class Solution:
    def firstUniqChar(self, s):
        counts = {}
        for letter in s:
            counts[letter] = counts.get(letter, 0) + 1

        for index in range(len(s)):
            if counts[s[index]] == 1:
                return index
        return -1


solution = Solution()
assert solution.firstUniqChar("leetcode") == 0
assert solution.firstUniqChar("loveleetcode") == 2
assert solution.firstUniqChar("aabb") == -1
assert solution.firstUniqChar("aabc") == 2
assert solution.firstUniqChar("z") == 0
assert solution.firstUniqChar("") == -1
assert solution.firstUniqChar("abacbd") == 3
```

你的`seen`保存次数，`word`保存每个字符最后出现的索引。虽然重复字符的索引被更新，但最后只查询次数为1的字符；这种字符只有一次出现，所以它的最后位置也就是唯一位置，没有错误。

你按照`seen.items()`顺序找到第一个次数为1的字符，这在当前Python中也正确：字典保持键首次插入的顺序，更新已有键的值不会把键挪到最后。由于你从左到右插入字符，筛出的第一个唯一字符就是最靠左的唯一字符。不能误判成“字典无序，所以你的算法不成立”。[Python字典顺序规则](https://docs.python.org/3.11/library/stdtypes.html#mapping-types-dict)

示范只保留计数字典，第二遍直接走原字符串，因此不需要保存索引的第二个字典，也不依赖读者理解字典遍历顺序。它的优点是少保存一份状态，不是你的答案必须推倒重写。

### 02：神经元，给模型传入一组样本

先给出昨天要求的“普通函数版”完整示范：

```python
class SingleNeuron:
    def __init__(self, weight, bias):
        self.weight = weight
        self.bias = bias

    def forward(self, x):
        z = self.weight * x + self.bias
        if z > 0:
            return z
        return 0


def predict_samples(model, samples):
    outputs = []
    for sample in samples:
        outputs.append(model.forward(sample))
    return outputs


neuron_a = SingleNeuron(2, 1)
neuron_b = SingleNeuron(-1, 3)
samples = [-1, 0, 2]
assert predict_samples(neuron_a, samples) == [0, 1, 5]
assert predict_samples(neuron_b, samples) == [4, 3, 1]
assert predict_samples(neuron_a, samples) == [0, 1, 5]
assert predict_samples(neuron_a, []) == []
assert predict_samples(neuron_a, [4]) == [9]
assert predict_samples(neuron_b, [5]) == [0]
assert samples == [-1, 0, 2]
assert neuron_a.weight == 2
assert neuron_a.bias == 1
assert neuron_b.weight == -1
assert neuron_b.bias == 3
```

你写的是`SingleNeuron`里面的`predict_samples(self, samples)`，也就是方法版；它使用`self.forward(sample)`。这种设计本身合理，而且计算正确。

## 四、Python新理论：保留“走到这里的结果”

### 1. 累计状态与前缀和

累计状态（running state）是程序处理到某个位置时，保存的阶段信息。人话：不只知道眼前这个数，还记着前面已经算到了哪里。这里的“状态”不是一种新语法，就是你自己决定保存的变量。

前缀和（prefix sum）指从序列开头一直加到某个位置的和。“前缀”就是从开头取的一段。题名里的“动态和”不表示今天要学动态规划。

例如三段任务耗时是6、2、5毫秒：

| 位置 | 这一段耗时 | 到这里累计耗时 |
|---:|---:|---:|
| 0 | 6 | 6 |
| 1 | 2 | 6＋2＝8 |
| 2 | 5 | 6＋2＋5＝13 |

求总和只需交回13；今天需要交回[6, 8, 13]，因为别人想知道每一阶段结束时累计用了多久。结果列表的长度与输入相同。

处理到第二项时，已经知道前两项总和是8。下一项是5，再得到13时，不需要把6和2重新算一遍。这是“利用已经得到的信息”，不是背一个固定循环。你决定代码里怎样保存它。

累计值不一定越来越大：输入[4, -6, 3]，各阶段是[4, -2, 1]。负数可以让总和变小，别把“累计”误解为“只会增加”。

### 2. 一个当前值与一份历史列表，各自解决什么问题

当前值用于继续计算；历史列表用于交付每个位置的结果。它们职责不同。下面只演示列表怎样保存整数，不是动态和答案：

~~~python
history = []
current = 4
history.append(current)
current = 9
assert history == [4]
history.append(current)
assert history == [4, 9]
~~~

逐行看：

- 第一行建立空列表，准备放结果。
- current先是整数4。append把这个整数放到列表尾部。
- current后来改为9，是把变量重新指向整数9；列表先前那项仍是4，不会跟着变成9。
- 再追加一次后，列表才有第二项9。

这里说的是整数的行为，不是在讲“所有对象加入列表都会深复制”。可变对象的共享问题等实际需要时再展开。

方法最后需要return结果列表，print只是显示结果。LeetCode检查的是交回的值，不是终端里打印了什么。不要把每次调用的累计值长期保存在Solution实例上，否则第二次调用可能带着第一次的旧结果；每次任务自己的临时计算放在方法内部即可。

### 3. 从次数理解复杂度

若每来到一个数只做固定数量的加法与保存操作，n个数对应的工作量与n成正比，时间O(n)。

若每个位置都重新从头求一遍和，工作量是1＋2＋…＋n，规模大时是O(n²)。先做对，再检查自己是否重复算了已知信息；不要求第一次就“看到题立刻背出最优解”。

本课要求返回新列表，所以结果要保存n个整数：把输出也计入空间时是O(n)，不计输出列表时，单个累计值可只占O(1)。说清口径即可，不因一种写法的术语差异反复扣分。

## 六、C++基础理论：先看怎么算，再看存到哪里

### 1. int、double和表达式

类型（type）描述一个值按什么规则存储和参与运算。人话：变量不只是贴了个名字，还选了“装哪类数、按什么方式算”。

- int：存整数，例如3、0、2500。本课数字很小，不涉及溢出。
- double：一种浮点类型（floating-point type），可表示小数，例如2.5。它不是“绝对精确的小数”，也不是无限位；今天先用能准确表示的简单数值。
- 表达式（expression）：算出一个值的一小段代码，例如9 + 4或9 / 4.0。

~~~cpp
int count = 9;
double scale = 2.5;
count = 12;
~~~

第一行是声明并初始化：int说类型，count是名字，9是初值。第三行只是给已有变量换值，不需要再写一次int。每条这样的语句后要有分号。

int和double是C++内建类型，编译器本身认识，不是iostream提供的。9是整数写法；9.0虽然数学上也等于9，但在这里是double浮点写法，这个区别会影响除法。

### 2. 整数除法：结果装进double也来不及补回小数

整数除法（integer division）：两边都是整数时，C++除法得到整数，截掉小数部分。本课先只用非负数。

| 表达式 | 运算时使用的类型 | 结果 |
|---|---|---:|
| 9 / 4 | 两边int | 2 |
| 9 / 4.0 | 一边double | 2.25 |
| 9.0 / 4 | 一边double | 2.25 |

最容易误解的是：

~~~cpp
double late = 9 / 4;
~~~

计算顺序是：先按右边两个整数算9 / 4，得到2；再把2转换成double存给late。不是先看到左边double，就让右边自动保留小数。最终数值相当于2.0，默认打印时可能显示成2。

人话：你先把小数部分剪掉，再把整数放进能装小数的盒子，剪掉的内容不会长回来。

这也解释了9 / 4 * 1.0为什么还是2.0：乘除同级，从左往右算，丢失已经发生。9 * 1.0 / 4则在除法前就参与了浮点运算，结果2.25。括号可以改变计算组合；但(9 / 4) * 1.0仍是先做整数除法。

Python中9 / 4得到2.25；不要把Python的“/”习惯直接搬到C++。[C++乘除运算规则](https://learn.microsoft.com/en-us/cpp/cpp/multiplicative-operators-and-the-modulus-operator?view=msvc-170)、[基本类型说明](https://learn.microsoft.com/en-us/cpp/cpp/fundamental-types-cpp?view=msvc-170)

### 3. 小程序的外壳为什么存在

下面只验证上面的数值规则，不是毫秒换算或比例作业答案：

~~~cpp
#include <iostream>
#include <cassert>

int main() {
    int whole = 9 / 4;
    double late = 9 / 4;
    double decimal = 9 / 4.0;

    std::cout << whole << "\n";
    std::cout << late << "\n";
    std::cout << decimal << "\n";

    assert(whole == 2);
    assert(late == 2.0);
    assert(decimal == 2.25);
    return 0;
}
~~~

把这一小段看懂即可，不要求复制进作业：

- #include <iostream>引入标准输入输出工具的声明；今天只用输出。
- #include <cassert>提供assert检查。它接收一个条件，条件为假时报告失败并停止；条件为真不会自动打印“通过”。下面编译命令没有关闭断言。
- int main()是程序开始执行的位置；大括号圈住它的代码，return 0表示正常结束，不是把题目的答案交给LeetCode。
- std::cout是标准输出，通常显示在终端。std::表示标准库的名字范围，目前会识别即可，不展开命名空间体系。
- 连着的<<把右侧各项依次输出；"\n"表示换行，不是两个字符斜杠和n。
- ==比较两边是否相等；=才是赋值。assert是帮你发现错误，不会把错误答案自动改对。

预期三行输出是2、2、2.25。今天选的.25、.5、.75、.375等数可以用二进制精确表示，因此可以直接用相等断言检查这些小实验；这不是所有浮点计算都能用==的通用结论，容差在需要时专门讲。

### 2. 人工智能与机器学习，不是两个编程库

人工智能（artificial intelligence，AI）是研究和实现机器感知、学习、推理、决策等能力的领域。人话：我们希望机器能完成一些需要理解信息、判断情况的任务，“希望做到什么”是目标。

机器学习（machine learning，ML）是一类利用观察数据形成规律、再用于未知数据的方法，也是AI的重要分支。人话：不给机器逐个写死所有情况的答案，而是让它根据例子选出适合的计算规则或参数。

这不表示任何if程序都叫AI，也不表示AI只能用神经网络；神经网络是可用于学习的一类模型，今天只用最小的一种计算部件。

教材1.1.1按推理期、知识期、学习期介绍发展：可以把关注点粗略理解成“怎样按规则推导”→“怎样组织专家知识”→“怎样从例子学”。这是帮助理解方法需求的历史线索，不是说新方法出现后旧方法就全部失效。

1.1.2的符号主义（symbolism）强调用明确的符号和规则处理信息；连接主义（connectionism）强调由许多相连的简单计算单元完成信息处理，神经网络与它密切相关。知道两者关注点即可，不要求背流派名、学新的编程语言，也不用把它们理解成绝对互斥的阵营。

### 3. 明确规则与从数据学习，差别在哪

假设一个演示任务中，输入x应该对应输出y：

- 明确规则的版本：人直接告诉程序最终关系和参数，程序负责照着算。
- 学习版本：人规定可用的模型形式、候选参数以及怎样判断好坏，但最终用哪组参数，由样本决定。

不要误解成“机器学习就不需要人写程序了”。学习算法本身仍然是人编写的。区别是：人写的是怎样选参数，而不是为所有数据直接填好最终参数。

例如给你若干张不同温度与测量读数的对应表，人很难先保证一个校准系数永远正确。可以让程序根据已经测到的数据选择系数，再用它处理新读数。这只是帮助理解“数据影响参数”的例子，今天作业仍使用人工构造的小样本，不冒称解决了真实传感器问题。

模型（model）可以先理解为：一个接收输入、产生预测的计算规则。参数（parameter）是这个规则里能被选择或学习的数，例如weight和bias。数据（data）是你拿来观察和学习的样本，不是模型参数本身。

教材1.2讨论的是从有限观察中获得对未来有用的规律。“已有样本上算对”是检查的一部分，是否能处理未参与学习的输入还要另外测试。泛化（generalization）就是这种处理未见数据的能力；少量测试成功不等于保证所有未来数据都正确。

### 4. 为什么教材还讲输入表示

书内图1.2介绍传统机器学习的数据处理流程：原始数据经过清理、提取特征、转换特征，再用于预测。

特征（feature）是用来描述一个样本的信息。人话：真正交给模型参考的数字或属性。以估计耗时为例，“任务数量”可以是一个特征，“任务名称的一整段文字”却不能直接塞进我们目前这个只接收数值的神经元。

图中的几个词先理解作用：

- 数据预处理：把脏乱或不一致的数据处理成可用形式。
- 特征提取：从原始材料里选出、计算出有用的描述。
- 特征变换：把已有描述变为更适合后续模型的形式。
- 预测：模型根据这些输入给出结果。

这是教材解释的传统流程，不代表所有现代模型都必须把四步写成四个独立程序。今天不安装处理库，不学图中全部算法；DAY19围绕“类别怎样变成向量”具体实践。当前x已是一个数，所以可以直接进入已有神经元。

### 5. 复用神经元：公式里的量分别是什么

你已有的神经元先算：

**z＝w×x＋b，预测值＝ReLU(z)。**

w是权重weight，b是偏置bias，x是本次输入；ReLU是修正线性单元（rectified linear unit），在这里就是“正数原样保留，否则输出0”。今天复用这个已学计算，不增加多输入、矩阵或反向传播。

例如w＝3、b＝1、x＝2，先得到7，再经过ReLU仍是7。若x＝−1，先得到−2，再变成0。中间的z与最终输出不是永远相同。

标签（label）是样本给出的目标结果，通常记为y；预测值通常记为ŷ，读作“y帽”。人话：y是对照答案，ŷ是模型当前猜出的数。两者可能不同。DAY21会正式整理样本、特征、标签与数据集，今天先认清手上的这几个量。

现在假设x＝2、目标y＝7、偏置固定为1：

| 候选权重 | 当前预测 | 与目标7是否一致 |
|---:|---:|---|
| 1 | ReLU(1×2＋1)＝3 | 否 |
| 3 | ReLU(3×2＋1)＝7 | 是 |

这只说明一条样本怎样区分两种参数，并不是完整学习算法。正式作业要考虑整组样本，不能只因第一条碰巧一致就认定所有样本都符合。

今天为了把关键关系看清楚，限定为整数样本、三组候选权重、偏置固定，且保证恰好有一组候选权重符合全部训练样本。真实学习通常不可能完全匹配，DAY23会学怎样用损失衡量“差了多少”，DAY24—DAY27再学梯度与更新。

### 6. fit与forward：普通方法名，不是魔法开关

前向计算（forward computation）是使用当前参数，从输入算到预测。学习或拟合（fit）是根据数据确定、调整模型参数。

人话：forward像拿当前刻度的尺子去量；fit像根据已知标准重新校准尺子。量了一百次，不代表尺子已经自动校准过。

这两个名字在纯Python类中只是普通方法名。Python不会因为你把方法命名为fit就自动帮你训练；改变参数的逻辑仍要自己实现。forward中也没有自动发生学习。

| 调用 | 接收什么 | 完成什么 | 今天是否改变模型参数 |
|---|---|---|---|
| forward(x) | 一次输入 | 用当前weight、bias计算预测 | 否 |
| fit(xs, ys, candidate_weights) | 一组输入、对应目标、候选权重 | 按这些样本选出合适权重，保存给模型 | 是，只改当前模型的weight |

对象中的实例属性用于保留模型状态。“状态”在这里指学到了哪个weight以及固定的bias；一次预测用到的x仍是临时输入。这正是面向对象的实际用途：把模型保存的数和操作这些数的方法放在一起，而不是为了写类而写类。

本次改变self.weight是fit的职责，不是以前说的“不能乱改状态”。forward不应偷偷训练；fit则必须真的更新。判断应看方法约定，而不是一律禁止属性赋值。

模型A和B各有自己的参数；给A学习不能改掉B。A训练结束后，下一次forward自然使用A新保存的权重，不需要调用者把新权重再传进去。

### 7. 作业04：从候选权重中学习

文件：[04_模型实践_神经元候选参数学习.py](04_模型实践_神经元候选参数学习.py)。

允许复用DAY17里你已经理解的SingleNeuron初始化与forward；不要求重抄整段旧类。今天新增fit由你从空白完成。旧predict_samples方法可以保留，但不是今天核心，也不要求再写统计正输出函数。

接口与行为约定：

- 类名SingleNeuron，属性weight、bias沿用已有含义，forward仍做ReLU(w×x＋b)。
- 新方法fit(self, xs, ys, candidate_weights)中，xs与ys是等长的非空整数列表，相同位置是一组输入与目标；candidate_weights有三个互不相同的整数。
- 输入保证恰好一个候选权重在当前bias下能让所有训练样本的预测等于标签。无需处理“无解”“多解”、非法数据或浮点误差。
- 选出的权重写入当前模型的weight，并返回这个整数；bias不变，三个输入列表不变。
- 允许使用已学的循环、判断、索引、普通变量和方法调用。不需要import、继承或任何训练框架。
- 不直接硬编码某个权重，不直接绕过模型返回已知标签。修改训练数据后，要能选出不同参数。

测试分三轮。先手算一组预测，自己写三步分析、方法与断言，不预填实现：

| 轮次 | 模型初始/已有状态 | xs | ys | 候选权重 | fit返回、最终weight | 学习后新输入的预测 |
|---|---|---|---|---|---|---|
| A首次学习 | weight＝0，bias＝1 | [0, 1, 2] | [1, 3, 5] | [1, 2, 3] | 2 | forward(3)＝7 |
| B独立学习 | weight＝0，bias＝0 | [1, 2] | [3, 6] | [1, 2, 3] | 3 | forward(3)＝9 |
| A重新学习 | 沿用A，bias仍为1 | [0, 1, 2] | [1, 2, 3] | [1, 2, 3] | 1 | forward(3)＝4 |

再检查：B学习后A仍保持第一轮学到的参数；A重新学习后B仍保持自己的参数；每次fit均不改输入列表与bias。调用forward后weight也不应发生变化。这些检查直接验证“数据驱动学习”和“实例状态”，不是单纯增加形式要求。

A第一条输入为0时，三个候选权重都预测1；这条样本本身无法区分谁更合适。作业需要结合全部样本，而不是记住“第一条对上就行”。

这个实验叫什么、不叫什么：

- 它是有限候选参数搜索：在很小的候选集合中，根据样本选择配置，可看作最小的参数学习实验。
- 它没有计算梯度，不是反向传播；它只学weight，偏置暂时固定。
- 它复用一个真实的ReLU神经元计算，不是完整深度网络训练。
- 对新输入3预测正确，只验证这个人工任务的一次未见输入；不能据此说模型能理解任意数据。
- 本轮最终训练对象会换为不带ReLU的线性神经元，DAY22讲清差异，DAY25以后通过梯度更新，不把今天的候选搜索冒充最终训练项目。
